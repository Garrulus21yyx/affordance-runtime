# P4 MVP Realignment Plan

Goal: return P4 to the GUI Runtime research MVP, close only the safety properties required by the runnable vertical loop, and stop treating production-grade authorization/transaction machinery as a P5 prerequisite.

Status: **complete — P4 CLOSED (MVP scope); P5 admission unblocked, not started.**

## Admitted runtime and threat model

- one run, one coordinator, one browser session, one active immutable `ActionContract`;
- trusted in-process Runtime components and serial state mutation/effectful execution;
- no public/persistent/cross-process `DispatchPermit` capability;
- multi-tenant authorization, worker leases/fencing, distributed checkpointing, multiple controllers, hard-crash dispatch recovery, and release-grade benchmark attestation remain deferred;
- existing extra hardening may remain when harmless, but it is not a P4 acceptance dependency and must not expand the mainline design.

## P4-minimum exit gate

1. Executor accepts only a finalized immutable `ActionContract`.
2. Policy/approval evaluates that exact final contract: `approved_contract_hash == executed_contract_hash`.
3. Preflight rejects a stale snapshot/page/target/expiry; every rejection reaches zero Executor calls.
4. Completion requires applicable verifier evidence and actual required-output materialization; receipt alone cannot produce `DONE`.
5. An uncertain effectful attempt is not blindly retried.
