# General Assistant Shell Implementation Plan

Branch: `codex/supervised-gui-agent-ui`

Goal: turn the existing capability-agnostic Interaction Shell into a natural-language assistant surface that can answer directly, use mature retrieval, or invoke the existing GUI Runtime as one bounded capability without changing the GUI CoreLoop, World, Binder, ActionPolicy, evaluator, or benchmark profiles.

## Positive target contract

```text
natural user turn
-> one outer PydanticAI Assistant conversation
-> direct answer | mature retrieval tool | run_gui_task
-> polished user-facing response

run_gui_task
-> existing PublicSession / CoreAgentLoop / ActionPolicy
-> typed GUI task result + public progress/surface events
```

- The Shell and frontend are capability-agnostic; they never infer browser/search mode.
- The outer assistant owns user conversation history and final presentation only.
- The GUI Runtime exclusively owns TaskGoal revision, fresh World, GUI progress, currentness, execution, cancellation, confirmation, and effect reconciliation.
- A user goal change reaches the GUI ActionPolicy only through the existing consecutive `TaskGoal` revision path followed by a fresh World and GoalPlan rebuild.
- Cancel never becomes a model instruction; it is a typed Runtime control command.
- PydanticAI owns message/tool-call protocol, structured output, toolsets, cancellation, and usage.
- PydanticAI Harness owns compaction and optional namespaced memory; no custom memory store, summarizer, router state machine, or evidence path is added.

## Non-goals

- No change to benchmark tool availability or GUI benchmark scoring.
- No web-search shortcut inside the Browser tool profile.
- No second World, Binder, evaluator, GUI history, progress ledger, or currentness authority.
- No implicit storage of browser state, search claims, credentials, task progress, or model hypotheses as long-term memory.
- No live benchmark without separate authorization.

## Steps

1. `[completed]` Audit the current Shell session lifecycle, provider composition, public commands/events, PydanticAI model factory, and frontend command ownership; freeze the smallest coherent integration boundary.
2. `[completed]` Add the outer Assistant contract and PydanticAI composition using native message history, structured output, mature toolsets, Harness compaction, and opt-in namespaced Harness Memory.
3. `[completed]` Expose the existing GUI Runtime as one bounded `run_gui_task` capability and route in-flight respond/confirm/revise/cancel commands to the active PublicSession without copying GUI state into outer history.
4. `[completed]` Adapt the Shell session/application boundary and frontend to a general conversation: natural input, semantic activity, conditional live surface, safe interruption/revision, and polished multi-paragraph completion rendering.
5. `[completed]` Add owner-level and longitudinal tests for direct answer/retrieval/GUI selection, tool-pair history integrity, modification/cancel delivery, memory isolation, and final-answer presentation.
6. `[completed]` Run focused and full provider-free verification, generated-contract checks, fresh review, then one non-benchmark natural-language product smoke if the configured provider is available; commit the coherent change separately.
