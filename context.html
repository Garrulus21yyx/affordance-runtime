权威状态如何变成模型上下文

模型看到的不是 Runtime 全貌，而是按当前任务重建的有界投影。本页逐项说明哪些字段无损保留、哪些集合被截断、哪些内容只保留引用，以及压缩究竟做了什么。

本页结论：上下文控制主要靠“状态外置 + 每轮投影”，不是通用会话摘要。最危险的损失不是删掉旧对话，而是当前相关 affordance、观测文本或失败信号因预算未进入模型；因此控制字段必须无损，展示字段才能裁剪。

TaskSpec+StateKernel+BrowserSnapshot→PlanningRequest→PlannerContext→System + compact JSON messages→Compacted context（恢复时）
08-A

权威状态与观测 → PlanningRequest

输入 INPUT

完整 TaskSpec、StateKernel current state、BrowserSnapshot/PlannerObservationView、budgets 与 recent outcomes。

→

输出 OUTPUT

immutable request：identity、task/step views、bounded observation、outcome/recovery summary、budgets、allowed actions、admission facts。

转换者与规则：PlanningRequestBuilder 只读投影并核对构建前后 StateKernel 未变化；所有子视图绑定同一 task/state/snapshot identity。
输入域转换模型前请求损失/外置
TaskSpec关键字段投影objective/constraints/criteria非当前说明字段可能省略
StateKernel当前态投影plan/step/budgets/outcomes完整 Trace 不进入
Snapshot目标化 + 限额text/affordances/refs全量 DOM/像素/超限目标
Artifacts引用化/哈希selected refs文件正文和真实路径

保留语义

task/revision/state/snapshot identity、当前 objective/step、约束、证据缺口、剩余预算、允许动作与近期结果。

可能的语义损失

全量历史、旧 observation、未选 artifact、超限 targets/text、内部恢复细节；任务命名去除可能同时移除合法提示。

风险与防护

裁剪可能产生“模型看不到但页面存在”；0-choice/verification failure 可触发新观测，而 identity 防止拿旧上下文执行。

失败出口

projection stale/mismatch、必要字段缺失或 request 太大转 provider_context failure。

08-B

PlanningRequest → PlannerContext / model messages

输入 INPUT

typed request views、current task/step/observation、recent proposal/outcomes、verified effects。

→

输出 OUTPUT

一个 system prompt 与一个紧凑 JSON user message；PlannerContext 提供 bounded summaries、permitted actions 与 pending evidence。

转换者与规则：planning_request_serializer.py 做确定性序列化；PlannerContextBuilder 对 text、affordance summary、artifact refs、accepted knowledge 等设置上限。
Request field操作Message field语义风险
typed enums/objectsJSON 表示字符串/数组/对象类型语义依赖 schema prompt
observed_text截断bounded text尾部或低优先文本消失
affordances排序/限额summaries ≤ limit未入选目标不可见
artifact paths哈希/选择opaque refs路径语义与未选产物消失
history近期摘要latest/recent outcomes远期因果不直接可见

保留语义

所有控制不变量、当前步骤、当前候选空间、预算、验证/恢复摘要和 identity。

可能的语义损失

列表顺序和截断会形成注意力偏差；JSON 字符串不能完全表达 Python 类型约束；Prompt 只描述 schema 的可见部分。

风险与防护

模型可能把缺席当不存在；Runtime 在响应后重新校验 choice membership、identity 和 scope，不信任模型推断。

失败出口

model schema/parse failure 进入 repair schema；context overflow 进入 compaction owner。

08-C

PlannerContext → Compacted PlannerContext

输入 INPUT

当前 PlannerContext 及 presentation limits。

→

输出 OUTPUT

收紧后的 context：max_affordances、artifact refs、accepted knowledge 等可选预算下降；TaskSpec、snapshot、constraints、budgets、verifier state 继续保留。

转换者与规则：GeneralistLMPlanner.compact_planner_context() 通常将可选展示上限减半；PlannerContextCompactionOwner 要求 before/after 变化证据。

保留语义

任务权威、当前环境身份、硬约束、能力/审批处理、预算、未满足证据与验证状态。

可能的语义损失

更多 affordance、artifact ref 和 accepted knowledge 被删除；若真正目标处在列表后部，压缩可能直接降低成功率。

风险与防护

只压 presentation 层，不压控制层；压缩无变化被拒绝，后续可 switch provider 或重新观测。

失败出口

压缩后仍溢出、无变化或模型继续失败，转 provider switch/terminal，而非无限压缩。

08-D

完整历史 → Trace/Artifact 外置（而非聊天摘要）

输入 INPUT

全部 observations、contracts、receipts、verification、events 与 screenshots。

→

输出 OUTPUT

StateKernel 只留当前态；TraceDag/ArtifactStore 留完整可回放历史；Planner 每轮按需读取摘要/ref。

转换者与规则：RuntimeCommitter/ArtifactStore 外置历史。代码中不存在通用 conversation message 列表的滚动摘要或 Claude Code 式九段压缩。

保留语义

历史因果与产物仍在外部存储中，可通过 trace/evidence API 恢复。

可能的语义损失

“存储中存在”不等于“当前模型可见”；从 Trace 选择 recent summary 时仍会丢远期联系。仓库没有自动恢复任意历史语义的通用 memory retrieval。

风险与防护

模型可能重复旧错误；recent outcomes、attempted strategies 与 progress fingerprint 提供有限历史记忆。

失败出口

需要但未投影的历史信息只能由专门 recovery/reader 重新注入；当前实现不应宣称自动解决。

本页语义损失账本

转换边类型具体损失恢复性
Kernel/Snapshot → Request有界投影完整状态、DOM、旧历史Trace/artifacts 可查，未必自动注入
Request → Messages序列化降维类型约束、超限 text/targetsschema validation/新观测
Context → Compacted二次裁剪后部候选/refs/knowledge不可在同次 compact 自动恢复
History → External store可见性分离历史不在当前 prompt证据 API 可取；无通用检索器
