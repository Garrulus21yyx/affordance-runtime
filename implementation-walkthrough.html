01 · The whole object graph

先看一屏：24 个对象，只有一条可 dispatch 链

横向是一次任务的因果顺序，纵向是 authority。每次成功执行后，链路从 fresh World 重新开始，而不是沿用旧元素。

User / Shell① user turn→② PublicSessionCommand→pause / revise / takeover
Runtime③ NaturalLanguageTaskRequest→④ TaskGoal→⑤ GoalPlan?→⑪ ActionSpace
Surface⑥ BrowserGym reset/capture→⑦ raw AX/DOM/screenshot→⑧ SurfaceObservation
World⑨ WorldObservation→⑩ E/N/F/R projection→⑫ DeliveryPlan
Model boundary⑬ ModelTurnDelivery+⑭ ToolCatalog→⑮ ProviderEnvelope→⑯ ToolCall
Execution⑰ SelectAction→⑱ AdmittedSelection→⑲ BoundActionRequest→⑳ BrowserGym action
Closure㉑ Dispatch receipt+㉒ fresh post-World→㉓ ActionOutcome+㉔ TaskEvaluation / StepResult
面试时先说这句模型只拥有第 16 步“从当轮已交付工具中提出一个调用”；它不拥有第 7 步原始浏览器句柄、第 10 步 ref 分配、第 18 步合法性、第 19 步 binding、第 21 步 dispatch 真值或第 24 步任务成功。

02 · Natural conversation ingress

用户说一句话后，不是直接塞进 Agent prompt

自然语言、权限、并发 currentness 和公开进展分别有不同对象。Chatbox 的 Outer 只解决指代、修订、澄清和用户约束，不负责拆步骤；Benchmark 已经给出完整 instruction，所以直接从 Runtime intake 开始。两条入口最终都必须通过同一个 TargetRuntimeSession 和同一个 GoalCompiler。

→ Outer GuiTaskIntake(objective, constraints, material_inputs)
→ run_gui_task
                         ┐
Benchmark instruction ──┴→ NaturalLanguageTaskRequest → TaskGoal

01自然语言变成版本化公开命令PublicSessionCommand

产品入口先由 Outer 把 bounded recent turns 规范化为只有 objective / constraints / material_inputs 的 GuiTaskIntake；该 schema 故意没有 plan、steps、selector、tool 或 page state。_compile_gui_intake 只把这些用户条款确定性拼成现有 inner StartTask 文本，不调用第二个模型、不赋予操作顺序，也不扩大 deployment TaskBoundary 的 effect 权限。随后 TargetRuntimeSession.start(instruction) 创建 NaturalLanguageTaskRequest。v3 入口还要求 command_id + expected_task_revision + expected_run_status，同 ID 同 payload 可幂等返回；同 ID 不同 payload 是冲突。

IN"去 GitLab 找前三位 contributor 的邮箱"
OUTNaturalLanguageTaskRequest(request_id, instruction, boundary, revision=1)

代码：app/public_session.py · task/intake.py

02自然语言只描述意图，效果权限来自 typed boundaryThinTaskIntake

ThinTaskIntake.compile 不做网页规划，也不从文字猜授权。默认 TaskBoundary 是 READ_ONLY；如果任务会产生外部效果，调用方必须显式提供 allowed_effects 与 risk profile。allowed/forbidden 冲突直接 policy reject；非只读却没声明允许效果则进入 TaskInputRequired。

natural text + stable boundary
 request identity + revision
 constraints / allowed effects / success criteria / budget
 material inputs / evaluation spec / risk / requested outputs
→ TaskGoal  # 唯一目标 authority

这解释了为什么“用户说让我付款”不能仅靠 prompt 获得付款权限：语义理解与能力授权是两条链。

03公开事件与进度是投影，不是第二个状态机RuntimeSessionSnapshot

Session 对外发布 PublicRuntimeSessionSnapshot 与有 cursor 的事件流。每个 committed StepResult 被投影成 PublicProgressStep(step, status, label)；例如 “Checked the current page” 或 “Completed an interaction”。它适合 UI 展示，但不参与下一动作合法性，也不冒充 GoalPlan item completion。

公开 feed 还区分 UserTurn、GoalAccepted、RuntimeActivity、EvidenceSummary、InteractionRequested、RevisionApplied、ConfirmationRequired、Completion 和 Failure。Shell 只是 renderer；Runtime 仍是状态 owner。

03 · Goal compilation

任务如何拆解：一次静态编译，不是每步 planner

Authoritative

TaskGoal

完整用户意图、稳定限制、允许效果、输入、成功标准、输出和 revision。它可以被用户修订，但不能被 GoalPlan、网页或模型 prose 改写。

Advisory

GoalPlan

GoalCompiler 在 task start 或 revision 各调用一次；最多 8 项，每项只有 id、objective、done_when、depends_on、final。没有 mutable status、frontier 或成就账本。

Ready校验唯一 ID、依赖存在、DAG、最多一个 final
NotRequired短任务直接进入普通 loop
NeedsInput只有缺用户事实才 waiting_user
Unsupported / Failed记录 unavailable，普通 loop 继续

ActionPolicy 每一轮根据 TaskGoal + static GoalPlan + fresh World 自己判断现在该推进哪项。Runtime 不计算 “3/5 完成”，因为那会把开放世界语义偷偷变成另一个规则引擎。用户 revision 会让旧 plan 整体失效；URL 或 layout 变化不会触发自动 recompile。

为什么 Outer 后面仍有 GoalCompiler？Outer 只确认“用户要什么”，GoalCompiler 只给这个 TaskGoal 生成一次非权威依赖骨架。不能按来源关闭 compiler：否则产品与 Benchmark 会形成两套执行语义。若未来要减少一次模型调用，也必须让两种入口共同迁移到同一个返回 TaskGoal + GoalPlan 的 typed boundary，而不是只让 Chatbox 绕过。

代码：model/goal_compiler.py · goals/plan.py

04 · Browser ownership

BrowserGym 和 Playwright 到底各做什么

两者不是二选一。BrowserGym 是 benchmark/environment contract；Playwright 是它下面的真实浏览器与页面时序工具。项目在中间加的是 owner-thread、因果稳定屏障和统一 SurfaceAdapter，不是自造浏览器自动化框架。

Model只见语义工具 + E-ref

没有 Page、Locator、selector、BID 或坐标。

RuntimeBrowserGymSurfaceAdapter

把 raw observation 投影成 Surface/World，把 BoundActionRequest 转为 BrowserGym action。

BrowserGymGym reset / step / reward / task state

提供 benchmark 注册、标准 action、AX/DOM/screenshot observation、native task evaluator。

Playwright真实 page、navigation、DOM quiet、live probe

运行在 BrowserGym 专属同步 owner thread；句柄不跨线程、不进模型。

04专属线程封住同步 Playwright 生命周期ThreadBoundBrowserGym

BrowserGym 0.14 默认缓存 process-global synchronous Playwright。多个环境会复用错误 greenlet，关闭一个环境也可能停掉另一个。ThreadBoundBrowserGym 用 queue + Future 把 reset / capture_current / currentness_probe / causal_step / session_health / close 全部固定到一个 daemon owner thread，并把 BrowserGym 的全局 getter 改为 thread-local。

gym.make(task_id, headless=..., tags_to_mark="all") 仍是环境创建者；tags_to_mark="all" 让 SVG 子元素也获得私有 BID，减少坐标猜测。任何 Page、Locator 或 DOM handle 都不穿过线程边界。

05dispatch 一次，再等到可证明的 causal stable post-state_causal_step
  1. 在 authoritative page 上监听 navigation request、main-frame commit、DOMContentLoaded，并安装 MutationObserver。
  2. 只调用一次 environment.step(action)；记录 dispatch returned 时间。
  3. 若可能导航，给 450ms start grace；开始后最多等 5s commit / DOMContentLoaded。
  4. 在最终 page/document 上等待 DOM 连续 80ms quiet，最多 1.5s。
  5. 只有 stable 才调用 BrowserGym _get_obs()；pending/unstable 返回 typed transition，绝不把中间 DOM 当 fresh World。
BrowserGymStepTransition = {
  raw | None, reward, terminated, truncated, info,
  trace: before_url → after_url,
         document_epoch, navigation timestamps,
         STABLE_* | NAVIGATION_PENDING | ACQUISITION_UNSTABLE
}

这就是 dispatch → causal stable World → StepResult 的物理基础。普通 capture_current 不能覆盖一笔尚未闭合的导航，因为那会把“后来看到的任意页面”伪装成该 action 的因果 post-state。

06Playwright 只补物理事实，不改任务语义private control properties

BrowserGym 一次性捕获 AX/DOM。后端再用一个 browser-side bulk pass 为 BID 补充 attached、visible、enabled、readonly、editable、selected、active、focusable、bbox、options、gesture、navigation potential 等事实。大页面不会按每个 AX node 做一个 locator round trip。

这些仍是 private source facts。颜色只归一到有限 color family；并不会在 adapter 里推断“用户要点红色按钮”。页面语义、目标相关性和路线选择仍交给 ActionPolicy/VLM。

代码：surfaces/browsergym/backend.py

05 · Raw observation to fresh World

Adapter 如何把浏览器变成统一世界

BrowserGym
raw frame：AX tree、DOMSnapshot extras、screenshot、focused element、task/reward/verifier facts。
SurfaceAdapter
projection：project_browsergym_observation 生成 source observation + private binding rows；source revision、page identity、document epoch 与 capture frame 保留 lineage。
Orchestrator
selection：按 ObservationNeed 选 structural source；只有 residual visual purpose 才激活 VLM source。同一物理环境可用 grouped acquisition 保证同帧。
WorldFusion
fusion：合并 source targets/facts/topology，保留 provenance 与冲突；不在 Fusion 中猜网页业务。
World owner
fresh WorldObservation：新的 observation_id 成为唯一当前 GUI authority；上一 World 的 executable ref 立即失效。

为什么 VLM 是必要时开启，而不是“失败兜底”

ObservationOrchestrator 先用 structural baseline 满足 need。只有请求明确需要 visual property、target disambiguation、point grounding、text in image、spatial relation 或 visual change，并且当前 visual provider 宣告该能力，才产生 visual offer。VLM 输出的是 typed source evidence / proposal，再进入同一个 Fusion；它不能直接 click，也不会因为 “重复了三次” 自动接管。

“尽量无损”的准确含义Source → World 的公开语义骨架和 source topology 要保真；模型请求不可能把大型页面全文全量复制进去，所以 delivery 使用可恢复压缩：PageMap 展开当前 salient regions，折叠重复 collection，公开 coverage，并提供 read_region / search / list / cursor 取回完整 Record。省略必须可见、可追索，不能静默截断。

代码：surfaces/browsergym/environment.py · world/orchestrator.py · world/fusion.py

07 · Dynamic tools

动态 ToolCatalog 是当前世界的可执行切片

模型不发明工具，Core Loop 也不拼 schema。Registry 定义稳定语义词汇，ActionSpace 描述当前世界全部合法 action，DeliveryManifest 说明本轮真正交付了哪些 route；三者在模型边界编译成一次性 Catalog。

Stable Registry∩fresh ActionSpace∩DeliveryManifest= disposable ToolCatalog(context_id)

完整私有 ActionSpace

ActionSpaceBuilder 从 TaskGoal、fresh World、permissions 和 capability routes 生成当前全部语义 option。每项拥有 private action_id、operation、target、typed args 与 route；它是 Runtime admission authority，不因为 token 不够就消失。

有界公开 Delivery

ActionDeliveryPlan 选 base actions、当前 Top-K candidates、显式搜索命中和目的地，并写出 coverage/omission。模型只能调用 manifest 已交付 route；没交付不等于世界中不存在，可以先 read/search/find/page。

稳定工具族与 GUI 工具族如何组合

request_evidencecount_childrenread_regionsearch_page_contentlist_regionsfind_controlssubmit_final_responseask_userwaitabort

上面是闭合的本地操作词汇；Registry 拥有名称、描述、参数 JSON Schema、风险和执行类型。GUI operation 则按当前 capability 动态出现，例如 click(target.ref)、fill(target.ref, text)、drag(source.ref, destination.ref)、browser-context navigation。模型看到的是语义参数和 E-ref，不见 action_id、BID 或 selector。

10先构造 DeliveryPlan，再编译 schemaGroundedToolCatalogCompiler

Delivery planner 先保证 active form、当前交互对象、必要 destination 和目标 action 的原子前缀；再用剩余预算拓宽候选。Compiler 针对每个 operation 取 Registry schema，并用当前 resolver rows 收窄 ref domain。target-atomic obligation 不能只交付 target 文本却丢掉对应 tool route。

11调用时做第二次 current catalog resolutionprivate resolver

PydanticAI 返回 tool name、arguments 和 tool_call_id。Bridge 先确认恰好一个 current tool；Catalog resolver 再校验该名字确实属于当前 context、E-ref 属于该 operation 的可选域、参数通过 Registry schema，最后才生成 SelectAction 或本地 closed decision。过期 ref 不能因为字符串还长得像 E7 而执行。

TurnPacker 怎样在预算内逐步装箱

  1. 计算硬上限context_window − max_output − protocol_reserve − safety_margin。默认 profile 约 67k context、1,024 output、2,048 protocol reserve、1,024 safety，均可由 provider/profile 调整。

  5. 超限则结构化降级或 typed fail缩减可恢复 breadth，而非破坏 current obligation；即使最小合法包也放不下则 request admission 明确拒绝。

09 · PydanticAI boundary

为什么用 PydanticAI：借协议能力，不交出控制权

它负责

provider / SDK plumbing

typed message history、不同 provider 适配、tool schema 编码、tool_call_id、DeferredToolRequests、multimodal parts、stream/usage、官方消息序列化、有限 model retry 与 capture_run_messages。

它不负责

Runtime semantics

不决定网页有什么、哪个 ref 当前、动作是否合法、是否需确认、如何绑定 BID、dispatch 是否发生、UI effect 是否成立、任务是否完成，也不把 provider history 当世界真相。

项目使用 pydantic-ai-harness==0.25.0，因为这些 transport/message/tool-protocol 细节自己重写会产生大量跨 provider 漏洞；但 Bridge 外仍保留当前 Catalog 校验、one-current-call contract 和 Runtime evaluator。其设计重点是明确 boundary，不是用框架替代 Agent architecture。

12CanonicalProviderEnvelope 冻结一次物理请求content-addressed boundary

Binder 把 provider/model/profile identity、唯一 instruction、current user JSON、官方 history、pending deferred result、media 的实际 bytes/digest、tools、model settings、output contract、token reserves 全部绑定并 hash。Trace 记录的是这个 owner 已发出的 envelope，而不是事后从日志猜 prompt。

13GUI 工具一律 deferred，Runtime 执行DeferredToolRequests

普通 action request 使用 tool_choice=auto、parallel_tool_calls=false、temperature 0。Output validator 拒绝 text-only 成功；Bridge 要求恰好一个当前 tool call。若 provider 仍返回多个调用、未知工具或坏 schema，做有界 protocol/schema repair，仍不合法就 typed fail-closed。

合法调用不会被 PydanticAI 自动执行：它作为 DeferredToolRequest 返回。Runtime Catalog resolver、admission、risk、Binder、Executor 走完后，typed ToolReturn 才在下一轮交回 SDK history。

Harness summarization 何时发生，什么保留

阶段规则准确性保障
先投影过期历史旧 World prompt/media 删除，因为 current user request 已携带 fresh World；已闭合 ToolCall/ToolReturn 保留配对和业务结果，但移除 typed ephemeral ref path；未解决 tool suffix 完整保留。当前环境事实从不靠摘要恢复；旧 E-ref 不能继续拥有执行语义。
触发 compaction整请求压力达到可用预算 80%，或 history 达 50% 且至少可回收 15%；目标压至 30%，recent exact suffix 约占可用 history 12%，summary 输出上限 1,024。阈值针对 provider envelope 的实际 token breakdown；不是按字符串长度拍脑袋。
SummarizingCompactionpreserve_first_user_message=true、incremental=true；摘要只能用 Completed outcomes、Verified facts、Failed strategies 三类。结果值和来源优先；不把猜测提升为事实，不生成未来 todo，不保留临时 URL/ref。
边界验证验证官方消息 topology、ToolCall/ToolReturn pairing、unresolved suffix 与 exact preserved suffix。Harness 出错、发明 preserved message 或破坏配对时，回退原始 exact history；摘要失败不能污染控制流。
它不是数学意义的无损摘要自然语言摘要会丢细节。这里保证的是：fresh World 不摘要、未解决调用 exact、工具配对闭合、业务输出优先、旧执行 ref 清除、摘要可验证且失败回退。面试时不要把它包装成“完全无损 memory”。

代码：canonical_provider_envelope.py · pydantic_ai_bridge.py

10 · One CoreAgentLoop

一次 step 的真实路径：决策只是中点

Initialize
reset → first fresh World → one GoalCompiler call；建立唯一 RunState，不创建 Planner/Worker 第二 loop。
Context
若 observation/task revision 变化，重建 ActionSpace、canonical projection、region index、AgentContext、DeliveryPlan 和 Catalog。
Policy
用 TaskGoal + GoalPlan + fresh World + bounded history + current tools 产生一个 closed decision；返回的 context_id 必须仍当前。
Resolve
ToolCall → Catalog resolver → SelectAction；或直接成为 observation/read/search/wait/final/ask/abort 分支。
Gate
ActionSpace admission → replay guard → RiskPolicy/confirmation → Binder → environment currentness/live probe。
Dispatch
Executor 只发送一次 bound request；receipt 区分 NOT_SENT、SENT、SENT_UNKNOWN，未知副作用不盲重试。
Observe
同一 execution outcome 内取得 causal stable post-World；ActionEvaluator 只判断局部效果，TaskEvaluator/native verifier 判断整任务。
Commit
构造闭合 StepResult，然后才更新 workspace、Monitor、history checkpoint、observation delivery 和公开 progress。

Policy 能返回的闭合代数

SelectActionRequestObservationRequestActionPage / findLocalToolResult / read / searchWaitFinalResponseAskUserAbort

RequestObservation 只要求 Surface/Fusion 补证据；LocalToolResult 读内部完整 records，不 dispatch；AskUser 只在缺少用户拥有的事实时进入 waiting_user；FinalResponse 仍不能自行宣布 native task 成功；SelectAction 才进入 bind/execute。

14语义选择先过 action admissionAdmittedSelection

验证 action_id 属于当前完整 ActionSpace、目标和参数未被 provider 改写、operation 与当前 catalog 一致；ReplayGuard 检查近期相同 outcome identity，RiskPolicy 根据 typed effect/risk 决定直接放行、请求用户确认或拒绝。

15Binder 与 live currentness 后才允许 dispatchBoundActionRequest

Binder 解析私有 route 并派生 postcondition needs。Surface 比对 world/source revision、page identity、document epoch，并用 Playwright live probe 确认 BID attached/visible/enabled/editable。失败发生在 dispatch 前就是 NOT_SENT，可以 fresh observe 后重新推理。

16结果由 fresh post-World 闭合ActionOutcome + TaskEvaluation

dispatch 成功不是效果成功。ActionEvaluator 对比 before/after World 和 binding-owned postcondition，生成 local APPLIED/NO_CHANGE/REGRESSED/UNKNOWN 等 outcome；TaskEvaluator 或 BrowserGym native verifier 单独决定 SUCCEEDED/CONTINUE/FAILED。最后 StepResult 把 decision、receipt、post-World、effect、task evaluation 和 lineage 一次提交。

为什么普通 DeepSeek Flash 也可能做长链任务不是因为 Runtime 替模型写了网站规则，而是把每轮问题缩成：在 fresh、typed、可恢复展开的公共世界中，从当前合法工具里选一个语义动作。确定性的 currentness、binding、权限、dispatch truth、局部效果和终止由 Harness 兜住；开放世界理解、分解和选择仍由通用模型承担。

代码：agent/core_loop.py · actions/admission.py · browsergym/task_evaluator.py

11 · Memory and progress

没有一个叫“Memory”的万能桶：五层各自有边界

NOWfresh WorldObservation

唯一当前环境 authority。它回答“现在页面是什么”，不能由摘要或进度替代。

RECENTAgentWorkspace

最多 8 个 detailed steps、24 个 semantic events、每个 activity family 一条 summary；内容 ref-free，只支持短期策略连续性。

MODELPydanticAI official history

保存用户/模型/tool exchange；过期 current-state 句柄被投影，pair-safe prefix 可由 Harness 总结，unresolved suffix exact。

CONTROLMonitor + ObservationDeliveryStore

Monitor 保留最多 16 个近期 transition/result identity；delivery store 最多 64 个本地结果 digest receipt，只判断 novelty/stall，不保存 result body 供模型当记忆。

PUBLICSession event feed + PublicProgressStep

把 committed StepResult 变成用户能理解的活动标签和状态。它是 display projection，不反馈成第二个计划状态。

“进展”在系统里到底怎样表达

问题权威答案不该用什么回答
用户究竟要什么？最新 revision 的 TaskGoal旧聊天摘要、GoalPlan prose
页面现在是什么？fresh WorldObservation上一步截图、旧 E-ref、public progress
刚才动作有没有局部效果？ActionOutcome + dispatch receipt + before/after World模型说 “done”、DOM ID churn
任务是否完成？TaskEvaluator / native verifierGoalPlan item 打勾、Monitor 无 stall
最近路线是否在震荡？EpisodeMonitor 的同失败中心/transition identities不断清零的 recovery method 计数
用户 UI 显示到哪了？committed StepResult 的 PublicProgressStep/event feed把展示文案反喂给控制流

这就是为什么项目不维护 mutable milestone/todo：开放网页上的 “目标已满足” 往往只能由每轮 fresh World + model 语义重新判断，或由 native evaluator 终止。若 Runtime 自己缓存 item status，就会在页面变化、用户修订或先前误判后形成第二真相。

代码：agent/workspace.py · agent/monitor.py · observation_delivery.py

12 · Human-in-the-loop control

暂停、取消、修改、接管、返回、撤销不是同一个按钮

用户控制通过版本化 command 进入 TargetRuntimeSession。Runtime 在明确 safe boundary 承认它，而不是异步杀线程；每种操作都有不同的 temporal contract。

用户操作Runtime 做什么过去效果继续条件
Pause登记 cooperative request，在 BEFORE_POLICY / AFTER_POLICY / BEFORE_DISPATCH / AFTER_DISPATCH / AFTER_CAPTURE / AFTER_EVALUATION 等边界提交 checkpoint。保留resume 消费同一暂停状态；pending tool exchange 必须闭合。
Cancel在最近 safe boundary 终止未来动作，状态成为 cancelled；若覆盖 pending pause，产生 typed superseded outcome。不回滚run 终止。取消只保证“不再做”，不声称“从没做过”。
Revise先 durable pause；最多 6 turns / 16KiB 的 revision conversation 连同 current TaskGoal、pending question/confirmation 编译成完整 replacement proposal。先 reconciliation新 TaskGoal revision + fresh World + 新 GoalPlan；旧 plan/ref/context 全失效。
Take over到 durable pause，消费 checkpoint，把 control owner 改为 USER，签发 process-local input lease。保留只有持有精确 lease 的 surface input 才接收。
Return control先撤销旧 user lease，再 capture fresh World；捕获成功后才恢复 Agent。以 fresh World 为准若捕获失败，生成新 lease 并维持 manual control，旧 lease 永不复活。
Undo / 撤回效果不是通用时间倒流。只有 ActionSpace/EffectReconciliation 暴露可证明 compensation 时执行新的反向 action。显式补偿irreversible / unknown / unsupported 返回 typed needs-input/unsupported，不能伪造 rollback。

用户修改目标的完整分支

USERrevise_task

携带 command_id 与 expected revision/checkpoint。

→ pause
COMPILERreplacement TaskGoal

澄清对话只能补用户事实，不直接 patch 旧 GoalPlan。

→ reconcile
RUNTIMEeffect disposition

保留、补偿、needs input、unknown 或 unsupported。

→ recapture
WORLDfresh revision context

新 World、新 plan、新 catalog，旧执行句柄失效。

不能承诺通用 undo网页动作可能发邮件、付款、提交表单或触发远端 side effect。Browser snapshot 回退不了真实世界；最安全的合同是：dispatch truth 可追踪、取消阻止未来动作、可逆效果通过显式 compensation，未知/不可逆效果要求用户决策。
