# Affordance Runtime 转换审计单页设计

## 目标

保留现有 GitHub Pages 总览页的结构与内容，在其基础上为核心 E2E 章节增加独立详情页。详情页必须解释一步到下一步的具体数据转换，并显式记录可能发生的语义丢失、其风险以及当前代码中的防护机制。

## 已确认的信息架构

现有 `index.html` 继续承担全局架构图谱与连续摘要，不做结构性重写。新增九个详情页：

1. `entrypoints.html`：外部请求到 Runtime 信封。
2. `intake.html`：自然语言到 TaskSpec。
3. `planning.html`：TaskSpec 到 TaskPlan、PlanningRequest 与 ActionChoice。
4. `agent-loop.html`：StageInput 到 StageResult、RuntimeTransition 与权威提交。
5. `perception-action.html`：页面信号到统一观测、grounding、合同与执行回执。
6. `verification.html`：回执和后验观测到 effect、step、task 三层结论。
7. `recovery.html`：失败事实到 FailureEnvelope、owner 与恢复命令。
8. `context.html`：权威状态到有界模型上下文及压缩后的信息边界。
9. `evidence.html`：运行事件到 Trace、Artifact、评测和演化证据。

总览页对应章节新增明显的详情入口。每个详情页提供返回总览、上一章和下一章导航。

## 单页统一内容模板

每个详情页按实际调用链重复以下转换块，不允许只用一张总表代替正文：

1. 上一步输入对象及关键字段。
2. 转换者、调用符号与触发条件。
3. 字段级映射：复制、派生、规范化、过滤、截断、哈希、重新编号或外部化。
4. 输出对象、身份字段和直接下游消费者。
5. 明确保留的语义与不变量。
6. 删除、弱化、合并、截断、不可见或无法表达的语义。
7. 语义损失可能造成的错误或歧义。
8. 当前代码中的校验、来源追踪、拒绝、修复、重新观测或用户澄清机制。
9. 无法安全转换时的失败出口和下一所有者。

每页顶部增加一张“本页对象链”，末尾增加“本页语义损失账本”。损失必须区分：

- 有意丢弃：安全或最小权限要求下禁止向下游传播。
- 有界裁剪：为了模型上下文、成本或展示预算进行的可恢复裁剪。
- 表达降维：从丰富信号投影到有限 schema 后无法完整表达。
- 不确定性：当前观测或证据本身不足，不能伪装成已知。
- 真正缺陷风险：现有机制可能静默弱化语义且没有充分检测。

## 事实与措辞规则

- 每个转换块至少引用一个当前源码文件或具体类/函数。
- 区分“字段不存在”“字段未传给下游”“字段被外部化保存”三种情况。
- 不把模型摘要或执行器回执写成权威事实。
- 不把拒绝、澄清或 UNKNOWN 写成语义丢失；它们是防止静默丢失的显式结果。
- 对无法从代码证明的影响使用“可能”或“风险”，不得写成已发生事实。
- 源码链接绑定报告所分析的实现提交 `786857f8fb61aa99f2c7e6a23eb8225957e1438b`。

## 视觉与实现

- 复用现有 `styles.css` 与 `site.js`，新增详情页专用的转换卡、字段映射表、损失等级标签和章节导航样式。
- 使用静态 HTML，不引入构建工具或第三方运行时依赖。
- 移动端表格保持局部横向滚动，页面本身不得横向溢出。
- JavaScript 仅做导航增强；详情正文在禁用脚本时仍完整可读。

## 验收标准

- 九个详情页全部存在且可从总览对应章节进入。
- 每页至少包含两个真实转换块和一个语义损失账本。
- 所有详情页均有输入、转换、输出、保留、损失、风险、防护和失败出口。
- 上一章/下一章/返回总览链接无断链。
- HTML ID、片段、资源与本地链接检查通过。
- 桌面端与 320px 移动端无页面级横向溢出、无控制台错误。
- 全量仓库测试与 Ruff 继续通过。
- 更新并重新发布 `gh-pages`，公网 URL 返回 HTTP 200。

## 非目标

- 不重写或删除现有总览章节。
- 不把页面改造成面试问答题库。
- 不修改 Runtime 生产代码。
- 不声称实现仓库当前不存在的通用会话历史压缩。
