Conversion audit · 03 planning

TaskSpec 如何变成计划与下一动作

任务级规划决定“有哪些步骤”，步骤级规划决定“此刻选哪个合法动作”。两层都通过 Runtime-owned identity 和 authority 把模型建议与权威状态隔开。

← 上一章：编译返回总览下一章：Agent Loop →

本页结论：规划会主动丢弃自然语言的表面表达和页面全量细节，只保留可验证义务、当前步骤与当前候选。主要风险是计划粒度和候选过滤造成的语义收缩，因此每个投影都绑定 task/state/snapshot revision。

TaskSpec obligations→PlanCandidate→TaskPlan / StepSpec→PlanningRequest→ActionChoice set→PlannerProposal
03-A

TaskSpec obligations → PlanCandidate / StepSpec

输入 INPUT

objective、obligation DAG、source refs、evidence requirements、task revision。

→

输出 OUTPUT

每个 obligation 对应的 StepSpec，包含 objective、typed InteractionIntent、completion criteria、depends_on、preconditions。

转换者与规则：RulePlanCandidateGenerator 调用模块级 _step_from_obligation()，把 predicate/effect obligation 映射为步骤和 StateCriterion；无义务时走兼容性的 implicit-step fallback。
TaskSpec操作StepSpec可能变化
obligation_id身份映射step_id/source refs保留谱系
subject/relation/value类型投影InteractionIntent非交互修饰可能不进入 intent
evidence requirements准则生成StateCriterion证据策略显式化
depends_on边复制step dependencies计划顺序受约束

保留语义

义务身份、来源、依赖、预期状态与证据要求。

可能的语义损失

原始叙述顺序、修辞和多个义务之间未显式编码的软关联；一个义务一个步骤的粒度可能比用户心智模型更细或更粗。

风险与防护

Interaction 与 completion criterion 分离，防止把“如何做”混成“做成了”。义务 DAG 提供结构基准。

失败出口

无可表达 InteractionIntent、非法依赖或缺 evidence policy 时 candidate validation 失败。

03-B

PlanCandidate → 权威 TaskPlan

输入 INPUT

generator 产生的候选步骤、assumptions、source refs；可能来自规则或 provider。

→

输出 OUTPUT

具有 plan_id、version、based_on_state_version、supersedes 的权威 TaskPlan。

转换者与规则：TaskPlanAuthorityBinder/TaskPlanAuthority 校验候选并绑定运行时身份；provider candidate 被禁止携带 selector、xpath、coordinate、approval_token 和 plan authority。

保留语义

候选步骤、依赖、assumptions、生成来源和 task revision。

可能的语义损失

provider 自带 ID、状态版本和底层定位全部被丢弃；replacement plan 会替换未验证的未来路线，但保留已验证步骤。

风险与防护

重新绑定可能让 provider 的内部理由不可见，但防止它伪造权威。supersedes/version 记录替换链。

失败出口

候选包含禁止字段或 based_on state 过期时拒绝 admission/replan。

当前实现

PlanCandidate<StepSpec> → TaskPlanAuthorityBinder._subgoal_from_step() → TaskPlan<SubgoalSpec> → project_state_legacy_task_plan_to_step_view() → TaskPlanView<StepSpec>。_subgoal_from_step() 只取 completion_criteria[0]，并把 expected value 字符串化。

建议目标（尚未实现）

PlanCandidate<StepSpec> → TaskPlanAuthority → TaskPlan<StepSpec> + TaskProgress。删除默认生产权威中的 legacy SubgoalSpec 往返，但保留 plan admission、version 与 supersedes。

03-C

StateKernel + Snapshot → PlanningRequest

输入 INPUT

TaskSpec、TaskPlan/progress、active StepSpec、BrowserSnapshot、最近 outcomes/recovery、budgets。

→

输出 OUTPUT

不可变、bounded PlanningRequest，绑定 task/state/snapshot/page/environment identity。

转换者与规则：PlanningRequestBuilder 只读投影；serializer 将其压成一个 system message 与紧凑 JSON user message。
权威输入操作Planner 可见输出不可见内容
完整 StateKernel只读投影active plan/progress/budgets无关内部状态
BrowserSnapshot边界化affordances/text/artifact refs全量 DOM/图像像素
历史 Trace摘要选择recent outcomes/recovery完整旧轨迹
任务命名去泄漏语义摘要benchmark ID/命名线索

保留语义

当前任务身份、活跃步骤、允许动作、当前观测、已满足目标、证据缺口、预算与近期失败。

可能的语义损失

超过上限的 observed text、affordances、artifact refs、accepted knowledge 和较旧 outcomes；任务名去除也可能损失合法语义提示。

风险与防护

裁剪可能移除真正目标；保留 typed StepSpec/criteria、来源引用和当前身份，必要时通过 active perception/recovery 获取新证据。

失败出口

identity mismatch 或 stale projection 在构造阶段抛错，进入 provider-context/runtime recovery。

03-D

PlanningRequest → ActionChoice → PlannerProposal

输入 INPUT

active StepSpec、UnifiedObservation、允许动作种类与当前 grounding 结果。

→

输出 OUTPUT

Runtime-owned ActionChoice 集合；多选时模型返回 choice_id，最终转换为绑定 criterion IDs 的 PlannerProposal。

转换者与规则：ActionChoiceBuilder 纯函数生成候选；0 个失败、1 个 Runtime 自动选、多个才调用模型；响应验证 identity 与 membership。

保留语义

候选动作种类、目标、参数、destination、criterion IDs、来源与当前 snapshot identity。

可能的语义损失

不在候选集中的页面目标对模型完全不可见；模型自由生成的新动作、坐标和解释不会进入 proposal。候选构造错误会形成“选择前损失”。

风险与防护

严格候选提高安全但可能降低召回；0-choice 显式失败并可 reground/reobserve，而不是让模型猜坐标。

失败出口

grounding absent/ambiguous/capability_missing，或 choice ID 不属于集合时进入 typed planning failure。
