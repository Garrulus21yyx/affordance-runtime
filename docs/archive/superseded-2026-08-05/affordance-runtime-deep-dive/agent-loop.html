五阶段循环如何传递状态

Stage 不直接修改 Runtime。它接收分离的只读状态，输出 transition、events、failure 与 directive；唯一 committer 再把这些增量变成权威 StateKernel 和因果 Trace。

← 上一章：规划返回总览下一章：感知与执行 →

本页结论：循环中的主要语义变化是“完整内部状态 → 阶段所需投影 → 声明式增量 → 权威提交”。投影会隐藏无关状态，增量会丢弃阶段内部推理过程；Trace 记录结果和因果，不记录所有局部变量。

StateKernel→RuntimeStateSnapshot / StageInput→StageResult→RuntimeTransition→RuntimeCommitter→StateKernel + TraceDag
04-A

StateKernel → RuntimeStateSnapshot / StageInput

输入 INPUT

当前 plan/progress、observation、contract、receipt、verification、budgets、failure/recovery、state version。

→

输出 OUTPUT

分离且只读的 RuntimeStateSnapshot 与阶段专属输入；容器字段复制/冻结。

转换者与规则：Coordinator/phase 构造 StageInput；stage_protocol.py 定义 detached state view，阶段协作者不能获得 StateKernel 写引用。
权威状态操作阶段视图损失方式
当前对象复制/冻结projection copies对象身份与写能力丢失
完整状态面阶段选择所需字段无关状态不可见
state version保留绑定based_on version用于 stale check

保留语义

阶段决策需要的当前事实、任务/计划身份、预算和版本。

可能的语义损失

未投影状态、对象可变性、完整历史和其他阶段的内部细节不可见；错误投影可能让阶段误以为信息不存在。

风险与防护

类型化 StageInput、架构治理测试和版本绑定限制漏传与越权写入。

失败出口

输入身份不一致或必要字段缺失时阶段返回 typed failure，不直接修补 StateKernel。

04-B

StageInput → StageResult / RuntimeTransition

输入 INPUT

只读阶段状态及 collaborator 输出：捕获、planner proposal、contract/receipt、verification 或 recovery decision。

→

输出 OUTPUT

StageResult(output, transition, events, failure, terminal, directive)。

转换者与规则：Perception/Planning/Action/Progress/Recovery Stage 把内部计算投影成声明式状态增量和 LoopDirective。

保留语义

下游需要的产物、明确状态更新、可观察事件、失败信封、是否终态与下一控制指令。

可能的语义损失

阶段内部候选排序、中间局部变量、被拒绝的临时假设和 provider 推理不会全部进入 StageResult。

风险与防护

过窄 transition 可能丢失恢复所需事实；FailureEnvelope、events、artifact refs 和 debug key 保留诊断所需的最小集合。

失败出口

failure 与 terminal 是互斥的显式路径；directive 决定 repeat observation、recovery、user handoff 或 stop。

04-C

RuntimeTransition → StateKernel + Trace events

输入 INPUT

state_updates、phase、observation/perception、plan transition、proposal、contract/receipt、counters、progress、result、artifacts 和 ordered events。

→

输出 OUTPUT

新 state version 的 StateKernel、按因果父节点追加的 TraceNode，以及注册后的 artifacts。

转换者与规则：RuntimeCommitter.commit 按固定顺序应用增量；StateKernel 校验 phase/plan/progress 不变量，TraceDag 校验 parent 已存在。
Transition操作权威输出语义处理
state_updates原子提交StateKernel current state旧当前值被覆盖
events有序追加TraceDag nodes历史保留，不反灌 current state
artifacts外部化ArtifactRef大内容变路径+哈希
phase/directive状态机映射下一循环位置非法跃迁拒绝

保留语义

当前权威事实、状态版本、事件顺序/父子因果、外部产物引用。

可能的语义损失

StateKernel 只保留最新值，旧值需从 Trace 恢复；artifact 外部化后正文不在状态中；未发事件的内部事实无法回放。

风险与防护

单写者避免部分状态/事件分叉；固定提交顺序与 Trace parent validation 提供一致性。

失败出口

状态不变量或未知 Trace parent 失败时拒绝提交，属于 Runtime internal failure。

04-D

StageResult.directive → 下一阶段

输入 INPUT

当前 phase、terminal/failure、plan change、verification/progress 与预算。

→

输出 OUTPUT

再次感知、进入 planning/action/progress/recovery、等待用户、done/failed/aborted。

转换者与规则：RunCoordinator.run_sync 串行解释 directive；每次动作前后都经过显式阶段边界。

保留语义

控制原因、预算、失败所有者和终态条件。

可能的语义损失

复杂的多分支可能被收敛成单一下一 owner；Coordinator 是串行的，不表达并行候选探索。

风险与防护

串行化牺牲吞吐但简化权威；预算与 typed directive 防止隐式递归。

失败出口

预算耗尽、安全上限或不可恢复 failure 转 terminal；审批/澄清转等待状态。

当前实现

ProgressStage 捕获 post-action observation 完成 verification 后，下一 Coordinator turn 通常仍会进入 PerceptionStage 再 capture；当前没有保证复用同一 observation 的 directive。

建议目标（尚未实现）

增加 REUSE_LATEST_OBSERVATION 或 CONTINUE_WITH_OBSERVATION。只有 loading、证据冲突、verifier inconclusive、targeted perception 或 timeout 时重新捕获。

本页语义损失账本

转换边类型损失防护
Kernel → Snapshot隔离写权与无关状态typed projection + version
Stage internals → Result表达降维中间推理/临时候选events + failure envelope
Transition → Kernel当前态覆盖旧当前值TraceDag 保存历史
