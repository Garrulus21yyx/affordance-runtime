运行事实如何变成评测与可复用经验

Stage event、状态对象和大体积产物被分别写成 Trace DAG、JSONL 与 ArtifactRef；只有经过验证的语义轨迹才可能被挖掘成 TaskSkill，而且必须先隔离、回放和重新证明。

本页结论：证据链也会丢信息：对象序列化抹平类型和引用身份，大产物变成路径+哈希，指标聚合隐藏个例，技能挖掘抽象掉页面细节。Runtime 用因果父节点、digest binding、held-out replay 和 quarantine 防止“压缩后的成功故事”取代真实证据。

Stage events / Runtime objects→TraceNode + ArtifactRef→events.jsonl + run.json→Canonical verified trace→TaskSkill candidate→Replay evidence→Promotion decision
09-A

Stage events → TraceNode / TraceDag

输入 INPUT

event kind、payload、parent event IDs、run/environment/schema versions 与 artifact refs。

→

输出 OUTPUT

冻结的 TraceNode(id, kind, payload, parents, timestamp)，按顺序进入 TraceDag。

转换者与规则：TraceDag.add 生成序号 ID，冻结 payload/parents，并要求所有 parent 已经存在。
Event input操作Trace output损失
event kind标准化标签kind/id prefix调用栈名称不保留
payload objects冻结 JSON-likeimmutable payloadPython 类型/对象身份弱化
causal context显式父边parents未声明的隐含因果不出现
time采样timestamp_s细粒度内部时序可能缺失

保留语义

事件类型、发生顺序、显式因果父子、运行/环境/schema identity 和关键 payload。

可能的语义损失

未 emit 的内部决策、完整调用栈、对象类型行为、未显式建边的跨事件因果。

风险与防护

事件设计不充分会让回放误判；架构由 committer 统一发事件，parent validation 防止悬空因果。

失败出口

未知 parent 或不可冻结 payload 拒绝写入，属于 trace/commit internal failure。

09-B

Runtime objects → Artifact files / events.jsonl

输入 INPUT

Observation、screenshot、ExecutionReceipt、VerificationReport、TraceDag 与 run summary。

→

输出 OUTPUT

observations/*.json、screenshots/*.png、receipts/*.json、run.json、events.jsonl 与 ArtifactRef(path, sha256, media_type)。

转换者与规则：ArtifactStore 做安全路径校验、JSON 兼容转换与 SHA-256；JsonlTraceWriter 把 TraceNode 投影为 sequence/event_type/parents/state/artifact_refs/payload。

保留语义

完整序列化值、文件内容哈希、媒体类型、运行目录和事件顺序。

可能的语义损失

dataclass/Pydantic 类型、共享引用、方法和不可 JSON 值被抹平；大内容在上游模型/状态中只剩 ref；路径移动后 ref 可失效但哈希仍可验证内容。

风险与防护

序列化可能把不同类型压成相同 JSON；schema/runtime/contract versions 与 media type 辅助解释。

失败出口

绝对路径、..、unsafe run ID 被拒绝；缺文件不能 register。

09-C

Run evidence → Benchmark report / aggregate metrics

输入 INPUT

多场景/seed 的 terminal status、verification、runtime counters、failure categories、environment metadata。

→

输出 OUTPUT

benchmark report、success/verification/recovery/generalization 等聚合率、acceptance errors 和环境一致性报告。

转换者与规则：benchmark modules 聚合 BenchmarkRun；check_evidence.py 校验 acceptance、environment 与 replay categories。
单次运行聚合操作报告字段损失
status/evidence计数/比率success rates失败个例被平均
steps/cost/time统计efficiency metrics分布尾部可能被均值隐藏
failure codes分类聚合category rates根因细节丢失
environment版本绑定conformance metadata未记录环境变量不可复现

保留语义

场景结果、关键 Runtime rates、环境身份、acceptance errors 与报告来源。

可能的语义损失

平均指标隐藏长尾、少数严重安全失败和任务类型差异；只报总体成功率无法解释设计有效性。

风险与防护

报告同时保存 per-run 数据、failure categories、环境与多 seed；架构测试禁止产品路径导入 benchmark 特判。

失败出口

acceptance_errors、环境不一致或缺必要 evidence 使 release gate 失败。

09-D

Verified traces → TaskSkill candidate → replay promotion

输入 INPUT

成功终态、canonical semantic trace、任务/环境变体、验证证据与 action sequence。

→

输出 OUTPUT

归一化/聚类后的 TaskSkill candidate，先 quarantine；再由 original/task-family/held-out/global/safety replay evidence 决定晋升。

转换者与规则：SemanticTraceNormalizer/Clusterer 抽象页面变体；replay gate 要求独立 digest-bound reports、必要类别和效率/安全条件。
轨迹细节操作Skill 表示损失
具体 target IDs语义归一role/relation/action pattern页面实例细节
多条相似 trace聚类shared skill少数变体可能被视为噪声
成功证据digest 绑定replay evidence不能只复用原成功声明
candidate隔离quarantine未验证经验不进入默认路径

保留语义

可复用的动作/关系模式、来源 trace、验证身份、适用范围与独立回放结果。

可能的语义损失

具体页面上下文、罕见但重要分支、失败前兆和一次成功中的偶然因素会被抽象；聚类可能产生错误泛化。

风险与防护

错误技能会扩大到新任务；quarantine + held-out/safety replay + report digest 防止一次成功直接晋升。

失败出口

缺类别、无 fresh replay、digest 重用、不安全或无效率收益时保持 quarantine/reject。
