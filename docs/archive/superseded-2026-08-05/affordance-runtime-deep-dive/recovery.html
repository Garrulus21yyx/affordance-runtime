错误如何变成安全恢复

异常文本不能直接驱动重试。Runtime 先把错误、状态谱系和外部效果不确定性封装成 FailureEnvelope，再分类 owner、策略与必须改变的维度。

本页结论：恢复转换会主动压缩 provider/exception 细节为稳定语义族，便于跨运行聚合；但过度归一可能把不同根因合并。因此系统同时保留 semantic family key、exact debug key、evidence refs 和 effect status。

Phase error / exception / rejected proposal→FailureEnvelope→FailureKind + Owner→RecoveryDecision→Changed command→RecoveryOutcome
07-A

阶段错误 → FailureEnvelope

输入 INPUT

phase、exception/error code、message、state/task/plan/snapshot/proposal/contract/receipt、budgets、evidence。

→

输出 OUTPUT

统一 FailureEnvelope：failure class、semantic/exact keys、effect status、lineage、attempts、recoverable 与剩余预算。

转换者与规则：make_failure_envelope 红acted/normalizes message，生成语义哈希和精确调试哈希；infer_effect_status 根据 phase/receipt 判断外部效果。
错误事实操作FailureEnvelope语义变化
error message规范化/截断message ≤ 500URL/ID/数字细节可能被替换
phase + expected effect语义哈希family key同类错误可聚合
完整 debug context安全映射exact key敏感/不可序列字段不传播
receipt/timeout效果推断EffectStatus保留 may_have_occurred

保留语义

错误发生阶段、类别、稳定族、精确调试身份、运行谱系、证据、外部效果不确定性与预算。

可能的语义损失

原始 stack/message 中的选择器、长 ID、数字和 URL 被归一或截断；不同根因可能落入同一 family。

风险与防护

family collision 会选错恢复；exact_debug_key、phase、proposal rejection context、evidence refs 保留细分能力。

失败出口

Envelope 自身违反 effect/phase 谱系不变量时构造失败，转 Runtime internal/terminal。

07-B

FailureEnvelope → FailureOwner / RecoveryDecision

输入 INPUT

failure phase/class/code、effect status、attempted strategies、remaining budgets 与 current dimensions。

→

输出 OUTPUT

owner（runtime_recovery/progress/step_planner/task_planner/user/terminal）、RecoveryKind、changed dimensions、理由和预算。

转换者与规则：classify_failure 和 recovery coordinator 按 typed facts 路由；不是对 message 做通用关键词重试。
Failure facts路由Owner / Strategy被排除策略
stale snapshotmechanicalruntime / reobserve原样执行
schema/provider contextmodel ownerstep planner / repair/compact页面 reground
plan unsupportedtask ownertask planner / replan同一步重试
effect uncertainprogress ownerinspect post-state盲重放

保留语义

失败阶段、责任域、外部效果、已尝试策略、预算和需要改变的维度。

可能的语义损失

一个 failure 只能选择主要 owner；跨层复合根因被收敛为单一下一责任方，次要因素只留在 envelope。

风险与防护

选错 owner 会空转；owner identity、effect-status hard gates、attempt history 与预算限制错误升级。

失败出口

无安全策略、预算不足、不可逆未知效果或 recoverable=false 进入 user/terminal。

07-C

RecoveryDecision → Changed command / RecoveryOutcome

输入 INPUT

选定 owner/kind、current state fingerprint、required changed dimensions、evidence/budget。

→

输出 OUTPUT

reobserve/reground/reroute/compact/switch/repair/replan/inspect 等命令及有 evidence 的 changed outcome。

转换者与规则：RecoveryStage 只执行 Runtime mechanical recovery；RecoveryOwnerDispatcher 调其他 owner，并验证 before != after、changed dimensions 与 evidence。

保留语义

策略身份、恢复前后状态、实际改变维度、产出证据和剩余预算。

可能的语义损失

恢复命令通常只改变一个或少数维度，复合修复被拆成多轮；compact/switch 后 provider 内部上下文不完全连续。

风险与防护

分步恢复可能增加延迟；no-op 检测和 evidence requirement 阻止同策略伪装成新尝试。

失败出口

状态未变化、缺 evidence 或 owner mismatch 转 no-op failure，再升级 owner/terminal。

07-D

Uncertain execution → 对账、补偿或停止

输入 INPUT

execution timeout/verification failure、receipt dispatched 事实、idempotency/compensation 与 risk。

→

输出 OUTPUT

NOT_DISPATCHED / MAY_HAVE_OCCURRED / CONFIRMED_* / IRREVERSIBLE_OR_UNKNOWN，以及 inspect/retry/compensate/user handoff。

转换者与规则：effect status 是保守分类；只有确认未发生或幂等可证明时才考虑重试，补偿需要合同声明与授权。

保留语义

是否可能已产生副作用、风险、幂等与补偿边界。

可能的语义损失

MAY_HAVE_OCCURRED 把多种真实状态合并为一个不确定集合；这是刻意不猜测，不代表事实消失。

风险与防护

保守分类会减少自动恢复，但避免重复支付/发送/删除。独立对账尝试缩小不确定集合。

失败出口

仍不可确认且不可逆时停止自动执行，向用户呈现不确定状态与证据。
