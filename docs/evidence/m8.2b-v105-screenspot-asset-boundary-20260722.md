# M8.2B v105 ScreenSpot Asset Boundary

Date: 2026-07-22

## Gap

ScreenSpot annotations supplied an image filename that was joined directly to
the configured image root. A malformed absolute path, `..` component, or
escaping symlink could make the harness read bytes outside that asset root.
Separately, the evaluator correctly classified an unreadable image, but source
manifest hashing then retried the same read without error handling and crashed
instead of persisting a fail-closed report.

## Repair

- every annotation image resolves beneath the configured asset root before it
  can be read, hashed, or sent to a visual grounder;
- escaped paths are rejected before evaluation;
- source manifest entries use root-relative paths and include a digest or a
  redacted exception type;
- missing/unreadable images persist `source_image_errors` and an acceptance
  error while keeping `official_score_claimed=false`;
- no local path contents or external file bytes enter the prediction artifact.

## Validation

- focused ScreenSpot tests: `12 passed`;
- traversal rejection covers parent-path escape (the same resolver also bounds
  absolute paths and escaping symlinks);
- missing-image evaluation writes a complete report instead of raising during
  source-manifest hashing;
- full repository: `350 passed`;
- full Ruff: clean;
- mypy over ScreenSpot, WorkArena, and CLI production modules: clean;
- `git diff --check`: clean;
- local Ollama remains reachable; no stale BrowserGym/Playwright job remains;
- GitHub Actions, remote providers, and official benchmark assets were not
  used.

## Boundary

This proves the offline harness's asset isolation and failure reporting. It is
not a ScreenSpot score: official annotations/images and a versioned real
prediction artifact remain required.
