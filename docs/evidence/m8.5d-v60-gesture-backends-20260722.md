# M8.5D v60 Gesture Backend Evidence

Date: 2026-07-22

## Scope

This local slice completes the backend-neutral dual-target gesture path from a
validated `GestureBinding` into Playwright and bounded visual pointer adapters.
No model or remote provider was used.

## Core preflight

- Source and destination retain separate semantic ids, candidate ids,
  fingerprints, leases, and one selected route.
- Every execution preflight rechecks both endpoints against the current
  observation.
- Current `blocking_overlays` are checked against generic point/center/bbox
  endpoint geometry in Core. Backend-specific bids and selectors are not used
  for this decision.
- Capability, approval, risk, contract hash, and recovery remain on the normal
  `ActionContract` path.

## Backend encoders

- `PlaywrightGestureEncoder` consumes the immutable core binding and produces
  a source/destination locator pair. `DomExecutor` executes
  `source_locator.drag_to(destination_locator)`.
- `VisualGestureEncoder` consumes current point/center/bbox geometry and checks
  finite coordinates, positive viewport bounds, distinct endpoints, and a
  bounded move-step count.
- `VisualExecutor` executes move-to-source, button-down, bounded move-to-target,
  and button-up. A failed move still releases the pointer button.
- `BrowserSession` maps the bounded pointer commands to Playwright mouse
  primitives for real Chromium use.

## Real Chromium diagnostic

The existing isolated Python 3.12 BrowserGym/Playwright runtime ran two local
fixture paths against current source code:

- Native HTML5 drag: the Playwright adapter returned a successful receipt and
  the page's independent `drop` oracle became true.
- Canvas/desktop-style pointer drag: the Visual adapter returned a successful
  receipt and an independent destination `mouseup` oracle became true. Browser
  events showed source down, destination moves, and destination up.

The visual oracle deliberately used a non-native-draggable source. Native HTML5
drag-and-drop and raw pointer gestures are different browser interaction
protocols; the former belongs to the Playwright/DOM adapter and the latter to
the Visual/Desktop adapter.
