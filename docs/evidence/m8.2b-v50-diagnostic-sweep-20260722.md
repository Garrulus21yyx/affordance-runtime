## Evidence-led clusters

The dominant failure is not provider capacity. Four task families produced a
first planner context with zero affordances and only `ask_user` permitted:

- navigation: `click-link`, `navigate-tree` (both seeds);
- drag: `drag-items` (both seeds); and
- spatial/value: `grid-coordinate` (both seeds).

This is an `OBSERVATION / CONTEXT` gap in the current DOM-only BrowserGym
adapter. It must not be addressed by changing the model prompt. The action
schema already contains bounded mouse/drag primitives, but the Generalist
semantic binder currently exposes only bid-bound activate/fill/select/press.

The remaining failures are separately retained for follow-up: drag/point tasks
that terminate at reward zero, `use-slider` postcondition verification,
`email-inbox` execution failures, and navigation/read task sequencing. They
are not evidence of a batch-wide provider or schema failure.
