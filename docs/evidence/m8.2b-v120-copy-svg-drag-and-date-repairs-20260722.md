# M8.2B v120 Copy, SVG Drag, and Date Repairs

Date: 2026-07-22

## Scope

This dirty-tree diagnostic continues the repair ladder opened by the complete
v112 release measurement. It does not claim a replacement release score. It
closes three generic failures observed in `copy-paste-2`, `drag-shapes-2`, and
the date/time family.

## Repairs

- Exact copy/paste instructions are compiled from one ordinal non-sensitive
  textarea source to one input destination. The planner emits semantic
  `TYPE_TEXT`, then exposes the terminal control only after the current input
  value exactly matches the source. Generic scroll discovery cannot pre-empt
  this transfer.
- The selective SVG observer now includes task-relevant primitives without DOM
  ids, derives stable unique observation ids, exposes color/type labels, and
  names duplicate outline containers as `left box` and `right box` from current
  geometry.
- SVG sources retain directional `drag`; outline destinations retain
  directional `drop` plus `accepts_drop`. Their unified candidate action is
  semantic `drag`, while planner source and destination allowlists remain
  distinct. The Core `GestureContractBinder` still owns endpoint distinction,
  current leases/fingerprints/epoch, compatibility, policy, and dual-target
  preflight. BrowserGym only encodes the valid binding to pointer drag.
- Explicit “all X to the left, everything else to the right” instructions are
  compiled as a generic labelled two-bin partition. No task id, bid, selector,
  bbox, or coordinate enters the planner proposal.
- Calendar day matching now accepts either the bounded `group_context` or
  `container_context`. This fixes the first day cell, which can lack the
  row-level group context even though its containing calendar proves the month
  and year.
