# M8.5D v62 Verified DOM-to-Visual Fallback Evidence

Date: 2026-07-22

## Scope

This slice proves the M8.5 exit gate in which one semantic target safely
recovers from a broken DOM route through a newly observed visual route. The old
contract is never mutated and the failed action is not blindly repeated.

## Controlled Coordinator regression

One `UnifiedAffordance` carries current DOM and visual candidates. The full
Coordinator path performs:

1. deterministic hard gates select the cheaper DOM candidate;
2. the injected DOM executor fails before dispatch and records
   `dispatched=false`;
3. recovery chooses `REROUTE`, excludes the failed candidate id, and returns to
   observation;
4. a new observation epoch provides fresh DOM and visual candidates;
5. the new RoutePlan records `candidate_excluded` for DOM and selects visual;
6. a new visual contract carries a different id plus
   `supersedes_contract_id`, root lineage, and fallback reason;
7. `VisualExecutor` changes the independent world state exactly once;
8. post-action observation and `observation_metadata` verification pass;
9. incident-local exclusions are cleared only after verified recovery.

The trace records route sources in order as `dom`, then `visual`; receipts are
`failed`, then `successful`.

## Real Chromium pixel-grounded diagnostic

The existing isolated Python 3.12 Playwright runtime executed the same recovery
shape against a local Chromium page:

- The semantic target was available as DOM plus a visual candidate detected
  from screenshot RGB pixels with a magenta threshold.
- The detected visual bbox was `[213, 147, 120, 60]`; no DOM geometry or hidden
  task coordinates were used to construct it.
- DOM execution was injected to fail before dispatch.
- Runtime captured fresh screenshots/observation epochs and selected visual on
  the second contract.
- The real mouse click set the page's independent `window.saved` oracle to
  true.
- Final status was `done`; verification was `passed`; route sources were
  `dom -> visual`; the second contract superseded the first.

No LLM/VLM provider was called, so this result is independent of the current
remote visual-model 429.
