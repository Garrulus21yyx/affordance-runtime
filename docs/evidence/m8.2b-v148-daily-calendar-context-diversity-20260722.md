# M8.2B v148 Daily Calendar Context Diversity

Date: 2026-07-22

## Failure attribution

The first real `daily-calendar:seed-0` vertical slice successfully created the
temporary calendar range with one semantic `DRAG`. The post-action DOM already
contained `#newEvent`, the event-name input, and the Create button. The runtime
nevertheless proposed the same drag again, and the no-blind-repeat guard
correctly blocked it until the episode budget expired.

This was an `OBSERVATION / CONTEXT` failure rather than a gesture, provider, or
Prompt failure. Each of the 48 physical half-hour cells intentionally exposes
distinct semantic start and end boundaries, producing 96 gesture affordances.
Their repeated whole-calendar `container_context` outranked the dynamically
rendered input and button in the planner's bounded 80-affordance projection.
The adapter had observed the controls and advertised `type_text`/`activate`, but
the bounded PlannerContext had omitted their targets.

## Generic repair

The bounded inventory now treats broad `container_context`, `context_text`, and
`group_context` as disambiguation evidence rather than target-local relevance
evidence. It also reserves a small representation for every currently observed
action family before filling the remaining budget by relevance and confidence.
The inventory remains capped at 80; the repair does not enlarge the context
window, add a task-ID branch, weaken current-lease contracts, or bypass the
no-repeat guard.

An adversarial regression gives the dynamic input and Create button confidence
0.1 behind 96 high-confidence calendar endpoints. Both controls and the
required 4PM range endpoints remain in the bounded inventory. The real
post-drag transition is now:

```text
DRAG(current semantic start, current semantic end)
-> fresh observation
-> TYPE_TEXT(current event-name target, exact requested name)
-> fresh observation
-> ACTIVATE(current Create target)
-> official terminal verification
```

Planner proposals contain semantic IDs only. BrowserGym alone encodes the
validated dual-target gesture as a pointer drag.
