## Generalist Planner Follow-up

The first three attempted Zhipu BrowserGym `click-button` PR checkpoints
revealed that the former schema unnecessarily required model-authored runtime
identity fields. The model instead returned semantic aliases such as
`expected_effect` and `evidence_need`. `GeneralistLMPlanner` now requests a
strict semantic candidate and binds proposal id, task revision, state version,
and snapshot id locally before constructing the final `PlannerProposal`.

A direct regression test proves that the candidate schema rejects model-supplied
identity values while the runtime binds those fields and retains the semantic
effects/evidence aliases. The
post-fix one-episode BrowserGym smoke then reached the configured Zhipu endpoint
but received HTTP 429 before any browser action. It is a resumable external
rate-limit diagnostic, not a score or failure of the local planner boundary.
