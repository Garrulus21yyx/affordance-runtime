## Next repair order

Repairs must be cluster-derived, generic, and replayed before another release:

1. close acceptance/schema defects (`schema_incompatible` and hard runtime
   failures) without weakening policy or evidence gates;
2. add explicit observation/action support for coherent visual/canvas families;
3. reconcile date/time and multi-step form execution/verification;
4. evaluate planning budget only after action/observation gaps are removed.

Initial trace triage supports that order. `copy-paste-2` successfully binds and
verifies the ordinal source value and destination input, but then exposes
unrelated scroll targets instead of the pending Submit terminal and eventually
fails semantic action matching. `drag-shapes-2` exposes duplicate container
points rather than draggable shapes/drop zones; a repair turn then reaches an
empty target allowlist and surfaces a raw empty-`Literal` assertion. The former
is sequence/target filtering; the latter combines an observation capability gap
with missing graceful handling of an empty repair domain.
