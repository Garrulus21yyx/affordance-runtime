# M8.2B v132 Structured Quantity Controls

Date: 2026-07-22

## Failure and generic repair

The v131 seed-major rescan reproduced `order-food` as
`observation_no_affordances` on both sampled seeds. The page contained current
HTML and BrowserGym `bid` values, but its custom plus/minus controls were not in
the BrowserGym set of marks. Treating every visible `bid` as actionable would
have admitted unrelated containers and decorations.

The repair instead derives a bounded semantic quantity control only when the
authored DOM provides all required evidence:

- an item container supplies the item name and current quantity;
- authored image metadata supplies zero or more item types;
- one child control supplies an unambiguous increment/decrement direction;
- the ordinary terminal remains a separately bound native control.

Off-viewport observation bypasses only BrowserGym's current viewport ratio. It
does not bypass authored `hidden`, `aria-hidden`, `display:none`, or
`visibility:hidden`. Planner proposals contain only current semantic target
IDs. Each increment creates and executes a normal current-lease contract,
causes a new observation, and changes the quantity-bearing fingerprint before
the next semantic operation is selected. The terminal is selected only after
the requested names or item-type count is satisfied.

An intermediate v131 five-seed replay is important negative evidence. After
the observation repair it exposed 25 current affordances per episode, but the
bounded planner projection retained container prose ahead of the
action-relevant `item_types`, `quantity_delta`, and `repeatable` fields. Every
seed therefore selected only `Order!`, made one model call, and scored zero.
The final repair keeps the projection strictly bounded while retaining the
defined quantity fields; it does not bypass contracts or weaken repeat
protection. The intermediate report hash is
`20dbf167b07035bedc2b605b55c49633a51d283635c24901c04e6f694ecc070d`.
