## Objective

Produce a new strict-generalist BrowserGym diagnostic under one immutable run
identity. Historical compatibility, nightly, and release scores remain
ineligible. This plan does not authorize task-family repair, remote providers,
GitHub Actions, `.env` publication, external-suite provisioning, or score
promotion.

## Fixed protocol

1. **Smoke / PR Gate**: 6 then 18 episodes using the fixed local provider and
   budgets. Stop the batch only for an allowlisted provider/infra, source/oracle,
   schema-wide, artifact, safety, or comparability failure.
2. **Diagnostic Sweep**: the versioned 30-task action-family manifest, seed 0
   then seed 1. Collect all ordinary failures before analysis; never repair in
   the running batch.
3. **Frozen Nightly**: only after diagnostic review freezes git SHA, model,
   prompt, schema, context policy, budgets, task manifest, and environment.
   Schedule all 30 tasks seed-major across ten seeds. Ordinary task failures do
   not stop collection.

`--resume` is valid only for machine interruption under the exact immutable
identity. Any code, Prompt, schema, context policy, model, or budget change
requires a new output directory.

## Evaluation boundary

- Test cases are the immutable task/seed schedule and expected accounting
  records; BrowserGym official reward remains independent from Runtime status.
- Trace events, contracts, receipts, verifier results, model-call records, and
  FailureEnvelopes are the execution event stream. No LLM-as-judge is used.
- Deterministic grading checks complete accounting, identity, safety, Runtime
  verification, provider health, and official reward separately.
- Diagnostic failures are clustered only after collection by root layer,
  action family, and failure signature. Development repairs must later be
  validated on the failed case, family seeds, PR 18, cross-family regression,
  a new diagnostic, then a new nightly.
