# M8.2B Slider Observation Context

This local observation check addresses an information gap in the current
Generalist BrowserGym form path. It is not a remote-model score or a claim that
the form/slider task is solved.

The official MiniWoB `form-sequence` page renders its current slider value in a
nearby visible text node while the keyboard-focusable slider handle itself has
no accessible value attribute. The DOM adapter now retains a concise nearest
ancestor display-text value only for keyboard-focusable custom controls in the
handle's `state.context_text`. This avoids duplicating broad container text for
native controls. The planner prompt labels that field as untrusted observation
and still requires post-action verification.

In the isolated pinned BrowserGym environment, seed `0` reset to goal
`Select 7 with the slider, click the 3rd checkbox, then hit Submit.` and
produced this focusable affordance state:

```text
('ui-slider-handle', 'press',
 {'enabled': True, 'visible': True, 'context_text': '-1'})
```

The local regression command is:

```bash
python -m pytest -q tests/test_dom_adapter.py tests/test_generalist_planner.py
```

The BrowserGym Generalist planner now receives the same action budget as its
episode Coordinator, rather than the generic five-effectful-action default.
This preserves bounded execution while allowing a generic range control to
move from a known boundary to an absolute requested value over several key
presses.

The optional BrowserGym profile must additionally be installed to reproduce the
official page reset. This evidence proves bounded observation preservation only;
the next current-planner BrowserGym matrix is required to establish whether the
model uses the observation to close the remaining form/slider behavioral gap.
