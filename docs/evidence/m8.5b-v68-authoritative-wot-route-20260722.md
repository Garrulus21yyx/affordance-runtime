# M8.5B v68 Authoritative WoT Route Evidence

Date: 2026-07-22

## Scope

This closes the M8.5 exit condition that an authoritative WoT/API candidate can
outrank a simultaneous GUI route when the task requires device state.

## Gap fixed

The planner correctly exposes only semantic `ACTIVATE`, but the typed
grounding boundary previously retained WoT backend verbs `invoke` and
`write_property` as candidate action kinds. Unified Route therefore rejected a
valid WoT candidate as `action_unsupported` before backend encoding.

`invoke` and `write_property` now normalize to semantic `activate`. The backend
contract still retains the concrete WoT locator, method, and operation.

## Coordinator proof

One semantic Power target contains current DOM and WoT candidates. A task whose
objective and evidence require the authoritative device property runs through:

~~~text
semantic ACTIVATE proposal
  -> device-state PerceptionRequirements
  -> DOM hard gate: source_not_acceptable
  -> WoT candidate selected
  -> fresh ActionContract
  -> capability/preflight
  -> WotExecutor POST
  -> fresh device observation
  -> independent metadata verification
  -> done
~~~

The final world state is `power=true`, verification passes, and the
`RouteSelected` trace source is `wot` even though a GUI candidate is present.
