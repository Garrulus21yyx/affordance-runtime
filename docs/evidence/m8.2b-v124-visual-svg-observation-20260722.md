# M8.2B v124 Visual SVG Observation Repair

Date: 2026-07-22

## Failure and root cause

The immutable v112 release recorded `click-shape` as
`observation_no_affordances` for every seed. A fresh five-seed reproduction on
the current tree produced the same structured `OBSERVATION / CONTEXT` cluster:
the page contained clickable SVG text, but the planner inventory was empty and
the safe result was `ask_user`.

Two generic observation defects composed into that failure:

- BrowserSession collected SVG geometry only for spatial requirements, although
  pure visual requirements also declared SVG acceptable and preferred.
- perception tokenization retained `click-shape` as one compound token but did
  not expose its `shape` component. The live objective (`Click on a small black
  8`) therefore did not independently request visual evidence.

The repair collects selective SVG geometry when either visual appearance or
spatial evidence is required, and retains both whole and component tokens for
hyphenated/underscored identifiers. Normal structured forms still use the lazy
DOM/A11Y path. SVG observation, screenshot, and DOM remain bound to one
coherent observation epoch; the planner receives semantic ids rather than raw
coordinates.
