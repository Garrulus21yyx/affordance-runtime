# M8.6 G4 Complete-Run Audit Execution Plan

Date: 2026-07-24
Status: complete

## Goal and fixed boundaries

Close G4 by making complete-run accounting, resumability, batch invalidation,
and post-collection clustering enforceable in generic evaluation contracts and
the BrowserGym consumer. Ordinary episode failure must remain local. Only a
declared batch-wide safety, integrity, comparability, isolation, provider/
infrastructure, or resource condition may stop or invalidate the matrix.

G4 does not authorize benchmark-family repair, prompt tuning, score promotion,
an expensive benchmark run, GitHub Actions, `.env` access, or a push. Runtime
verification and external reward remain separate facts. `--resume` may recover
only unobserved cases from the same immutable run identity.

## Initial findings

- BrowserGym already has seed-major scheduling, checkpoint metadata, atomic
  episode writes, failure envelopes, clustering, and batch circuit helpers.
- Existing evidence predates the stricter M8.6 boundary and must be audited for
  exact accounting, incomplete/invalidated distinction, resume lineage, and
  separation of Runtime verification from external reward.
- Current `run_complete` excludes missing registered tasks from its expected
  set, while report coverage includes them; the two truth sources can disagree.
- Current partial reports publish `failure_clusters` without marking them
  preliminary, so incomplete evidence can appear repair-selection ready.
- Current reports lack per-case disposition and do not distinguish resumable
  interruption/provider stop from integrity/comparability invalidation.
- G4 must not duplicate Runtime recovery or move benchmark concepts into
  Runtime core. Generic evaluation contracts may describe cases, dispositions,
  validity, and provenance; BrowserGym retains task/reward/source translation.

## Completion decision

G4 is complete. The complete-run protocol has one typed case ledger and one
immutable identity; partial, stopped, invalidated, and complete collections
cannot share a status. Ordinary failures never become batch stops. Formal
family and Runtime-owner clusters appear only after a complete comparable
collection, and external scoring remains promotion-blocked. The deterministic
30-case conformance collection is complete and clusterable, but is explicitly
not a benchmark result. G5 generalization proof remains pending.
