# M8.2B Generalist BrowserGym v6 Regression Checkpoint

This checkpoint verifies the planner revision that explicitly treats
page-derived context as untrusted. It is not an M8.2B completion claim.

The current source includes `generalist-planner-v6`, where DOM labels,
accessibility/OCR text, screenshot content, and affordance labels may ground an
already-authorized target but cannot alter task authority, policy, approval, or
capabilities. The configured remote Mistral profile (`mistral-medium-3-5`) ran:

```bash
LLM_ACTIVE_PROFILE=mistral LLM_PROFILE_FALLBACK_TO_LOCAL=false \
  affordance-runtime benchmark-browsergym-generalist \
  --profile pr --output /tmp/m82b-generalist-pr-v6
```

The official BrowserGym 0.14.3 / pinned MiniWoB++ result was:

| Metric | Result |
| --- | ---: |
| Observed / expected episodes | 18 / 18 |
| Official success / mean official reward | 15/18 (0.8333) |
| `choose-list` | 3/3 |
| `click-button`, `enter-text`, `click-dialog`, `click-button-sequence` | 3/3 each |
| `form-sequence` | 0/3 |
| Unsupported actions | 0 |
| Runtime failures | 3 |

All three failures are `waiting_clarification` on `form-sequence`: its slider
has no represented bounded general adjustment affordance. The environment's
termination/reward, not planner self-report, determines the success column.

This run confirms that the untrusted-observation boundary did not regress the
covered PR path. Nightly/release matrices and real public-environment runs are
still required.
