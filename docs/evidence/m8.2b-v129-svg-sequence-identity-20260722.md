# M8.2B v129 SVG Sequence Identity Repair

Date: 2026-07-22

## Failure progression and root cause

The immutable v112 release recorded `ascending-numbers` as
`observation_no_affordances` on all five seeds. A current-tree seed-0 replay
reproduced the empty planner inventory. The page first renders SVG text 1..5;
after clicking 1 it replaces the text with unlabelled SVG rectangles carrying
authored `data-index` values 2..5.

The repair exposed four generic layers in order:

- compound semantic terms such as `ascending-numbers` now contribute their
  component terms, and explicit ascending/descending order is treated as a
  general ordered-collection relation requiring spatial/visual evidence;
- the SVG observer retains rendered numeric text and authored `data-index`
  identity, with visual properties included in the candidate evidence and
  target fingerprint;
- the deterministic planner selects the smallest currently rendered numeric
  semantic target after each new observation epoch;
- BrowserSession derives the source affordance identity from the stable SVG
  element identity rather than its current array ordinal. Removing number 2
  therefore cannot make number 3 inherit number 2's action signature.

The intermediate v126 replay is important negative evidence: it executed 1
and 2 correctly, then Core's no-blind-repeat guard blocked the next proposal
because the ordinal identity had been reused. The runtime did not weaken that
guard. Stable source identity fixed the false alias, after which v127 completed
all five current-epoch SVG actions.
