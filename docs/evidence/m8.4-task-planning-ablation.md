# M8.4 Adaptive Shallow Task Planning Evidence

This is a controlled runtime ablation, not a claim about a remote model's
general planning quality. It exercises the real Coordinator, immutable plan
validation, verifier-backed subgoal progression, and independent final-stage
oracle with a deterministic structured-model fixture.

Command:

```bash
affordance-runtime benchmark-task-planning --output /tmp/m84-task-planning-ablation-v2
```

The report at the current working tree had no acceptance errors and declared
`remote_model_used=false`.

| Profile | Short success | Long success | Mean actions | Structured model calls |
| --- | ---: | ---: | ---: | ---: |
| Flat | 1.0 | 0.0 | 1.0 | 0 |
| Always-plan | 0.0 | 1.0 | 3.0 | 2 |
| Adaptive | 1.0 | 1.0 | 2.0 | 1 |

The short case has one independently verified stage. The long case has three
serial, verifier-backed stages. Flat prematurely completes one synthetic
subgoal and fails the final independent oracle. Always-plan performs all three
stages even when the short oracle requires one, so it fails that oracle.
Adaptive retains the flat short path and selects the structured task-planning
path for the three-stage case.

Every successful subgoal produced `SubgoalCompleted` after
`PostconditionPassed`; the long adaptive trace has three such events. This
proves the runtime sequencing and safety boundary, not that any particular
remote provider will choose equivalent decompositions.
