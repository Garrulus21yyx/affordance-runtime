# M8.2B v113 First Release-Cluster Repairs

Date: 2026-07-22

## Scope

The complete v112 release boundary exposed eight failure clusters across all
125 registered MiniWoB tasks. This dirty-tree v113 diagnostic closes two
generic runtime defects without claiming a new release score:

1. exhausted planner constraints constructed an invalid empty `Literal[()]`;
2. animated SVG presentation attributes made coherent multi-source capture
   and immediate preflight impossible on `click-pie`.

## Repairs

An empty initial or repair action/target domain now fails safe to typed
`ask_user` rather than constructing an invalid schema or inventing a target.
The five-seed `drag-shapes-2` replay contains no empty-Literal assertion; its
remaining failures are correctly attributed to `GROUNDING / ROUTING` because
the task still lacks draggable shape/drop-zone candidates.

Multi-source capture now compares URL plus the DOM Adapter's semantic page
revision at the start and end of an epoch. It still rejects actionable DOM
changes, but no longer rejects a stable page merely because decorative SVG
`transform` or `stroke-width` values animate.

When a low-risk `POINT_ACTIVATE` SVG/visual candidate retains page and semantic
identity but changes geometry fingerprint at immediate preflight, the
Coordinator does not ignore the mismatch or mutate the old contract. It runs
the current preflight snapshot through Unified Route and ContractBuilder,
rechecks policy/capability/preflight against a new contract hash, records
`ContractReboundAtPreflight`, and executes only the current epoch's point/bbox.

## Remaining boundary

This repair does not promote the v112 release result and does not erase its
other clusters. The next evidence-driven work is the systematic date/time and
multi-step execution family, followed by visual/canvas observation gaps and

repair ladder reaches a fresh breadth diagnostic on a new immutable candidate.
