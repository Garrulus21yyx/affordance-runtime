# M8.5H v65 Routing and System 1 Ablation Evidence

Date: 2026-07-22

## Scope

This is a controlled, provider-free runtime ablation over the six profiles
declared in the M8.5 plan:

1. DOM-only;
2. pure visual-only;
3. fixed DOM-to-visual cascade;
4. adaptive unified routing;
5. adaptive routing plus accepted TaskSkill;
6. always System 2.

Every run uses the real Coordinator, Unified Route Planner, fresh
ActionContracts, preflight, ExecutorRouter, post-action observation,
verification, and recovery. It is not a remote-model-quality claim.

## Core gap found and corrected

The first ablation attempt proved that pure visual and pure WoT candidates were
structurally impossible: `derive_perception_requirements` always required DOM
`TEXTUAL + STRUCTURAL` evidence even for explicitly visual or device-property
tasks. The derivation now selects required evidence by task semantics:

- ordinary structured tasks require textual and structural evidence;
- visual tasks require visual appearance, plus spatial evidence when needed;
- device/property tasks require authoritative device state plus structure;
- mixed tasks may require the union.

Focused route, perception, and cross-surface tests passed after this change.
`BrowserSession` also now exposes its owned locator boundary so it satisfies
the DOM executor protocol for Playwright gestures without leaking a browser
handle to the planner.

## Matrix

Each profile runs six cases, for 36 fresh Coordinator runs total:

- structured primary;
- visual primary;
- deterministic DOM failure before dispatch with visual fallback;
- material cross-source conflict;
- stale grounding candidates;
- accepted TaskSkill.

Effect cases require a verifier-backed final saved state with exactly one
effect. Conflict and stale cases require zero receipts/effects. All profiles
must retain zero unsafe side effects, verifier false accepts, and duplicate
effect risks.

## Results

| Profile | Success | Mean System 2 calls | Mean visual calls | Unnecessary structured visual call | Fallback | Skill-case System 2 calls |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| DOM-only | 0.6667 | 1.3333 | 0.0000 | 0 | 0 | 2 |
| visual-only | 1.0000 | 1.6667 | 3.0000 | 1 | 1 | 2 |
| fixed DOM-to-visual | 1.0000 | 1.8333 | 2.0000 | 0 | 1 | 2 |
| adaptive unified | 1.0000 | 1.8333 | 2.0000 | 0 | 1 | 2 |
| adaptive + TaskSkill | 1.0000 | 1.5000 | 2.0000 | 0 | 1 | 0 |
| always System 2 | 1.0000 | 1.8333 | 2.0000 | 0 | 1 | 2 |

All 36 runs passed their profile-specific oracle and the report contained zero
acceptance errors. Safety, false-accept, and duplicate-effect-risk rates were
`0.0` for every profile.

The report also records the remaining plan metrics explicitly: stale block is
`1.0` for every profile, constraint violation and provider cost are `0.0`, and
success regression delta versus always System 2 is `-0.3333` for DOM-only and
`0.0` for the other five profiles. Latency is retained per run, while the
provider-free harness makes no monetary cost or remote-quality claim.

The controlled cases intentionally show fixed cascade and adaptive unified
routing tying on success and observation cost. They do not yet contain a live
source whose acquisition cost/availability changes during the episode, so this
result does not claim adaptive superiority over fixed cascade. The live
cross-source conflict/provider family remains the next discriminating gate.

## Reproduction

~~~bash
affordance-runtime benchmark-adaptive-routing --output /tmp/m85-routing
~~~

profile aggregates, trace event sequences, oracle results, and acceptance
errors.
