## Runtime corrections

- BrowserGym verifies input value, selected option, keyboard/slider delta, and
  click state delta or positive terminal oracle separately from executor success.
- Coordinator blocks a repeated semantic action before execution as
  `effect_already_satisfied` or `no_progress_repeat` and returns to bounded
  replanning.
- Generalist planner v47 sends at most 80 ranked affordances, one recent
  proposal, one verified state delta, and one relevant failure. Bounded repair
  calls use a dynamically narrowed JSON schema for allowed action kinds,
  compatible targets, and parameterless actions; rejected progress signatures
  cannot re-enter the same repair chain. Numeric slider proposals are narrowed
  to the one direction that reduces distance to an unambiguous requested value.
  Explicit selection-only goals exclude incidental popup search inputs, and a
  successful select action collapses a transient overlay before the next action.
- HTTP provider failures are typed as `rate_limit_transient`,
  `quota_exhausted`, or `provider_capacity`. Gemini `google.rpc.RetryInfo` is
  parsed with a 30-second cap; quota exhaustion opens a resumable circuit-break
  deferral instead of issuing another request.
- BrowserGym checkpoint v2 records separate episode timeout, model-call
  timeout, maximum model calls, and execution reserve, plus per-episode model
  latency/retry/provider-failure statistics.

The current six-task seed-0 smoke at
`artifacts/m82b-v47-smoke/browsergym-report.json` passed 6/6 with mean official
reward 1.0, 18 model calls, 13,541.779 ms total
model latency, no retry/provider/runtime failure, and click/fill/press/select
coverage.

An intermediate v24 PR diagnostic completed 16/18 and exposed a semantic
repair bug: after the correct ordinal checkbox was verified, repair excluded
only that checkbox and admitted its wrong siblings. Subsequent nightly
diagnostics also exposed nested label/control aliases and A-B progress-history
loss. Planner v29 merges nested labels into their controls, scopes satisfied
targets to a stable page revision, and retains only labelled/ordinal controls
named by the task while preserving multi-target sequences.

Later long-form diagnostics found two additional attribution failures before
nightly. The shell-loaded `.env` still selected the Zhipu profile, so an
OpenAI-compatible `choices` response was inspected as if it were native Ollama;
pinning `local` plus the native Ollama adapter removed the apparent JSON
failure. A real `form-sequence` failure then showed a slider moving away from
an unambiguous numeric goal, while `form-sequence-3` exposed a verified select
whose custom popup remained over the requested button and admitted an
incidental search input. Planner v36 added direction-constrained repair,
selection-only action scoping, and select-overlay cleanup. The targeted
`form-sequence-2` and `form-sequence-3` matrices each passed 10/10 on native
GPU Ollama; the original `form-sequence` seed 6 also passed after repair.

A v36 nightly diagnostic then completed 89/300 episodes before intentional
interruption. Its first 80 episodes passed, including all activate, form,
`enter-text`, and `enter-text-2` seeds. All nine completed `enter-date` seeds
failed identically because Chromium rejects the user-facing `MM/DD/YYYY` value
for a native `input[type=date]`. Planner v37 preserves the semantic date while
the contract binding layer converts supported dates to ISO `YYYY-MM-DD`; the
targeted date matrix subsequently passed 10/10. The interrupted v36 report is
diagnostic evidence, not a nightly score.

The fresh single-version v47 PR report at
`artifacts/m82b-v47-pr/browsergym-report.json` passed 18/18 with:

- zero missing episodes, runtime failures, unsupported actions, provider

A later v37 nightly diagnostic reached 113/300 before autocomplete failures
were isolated. Planner v42 omits hidden menu trees and incidental labels,
exposes visible programmatic options without treating native `<option>` nodes
as click targets, preserves the supplied prefix, narrows candidates by explicit
prefix/suffix, and reserves `finish` for the official BrowserGym terminal
decision. The targeted autocomplete matrix then passed 10/10.

The fresh v42 nightly passed the first 30 activation episodes, then stopped at
35/300 on `form-sequence` seed 1. The objective contained both slider target
`-3` and checkbox ordinal `1st`; the previous direction guard intentionally
declined objectives with multiple numeric tokens, so three invalid direction
repairs ended before execution. Planner v43 now extracts the number
grammatically attached to the slider instruction. The targeted
`form-sequence` matrix passes 10/10 with 129 model calls and 90,259.512 ms
aggregate model latency. This interrupted v42 run is diagnostic evidence, not
a nightly score.

The next v43 nightly passed 130/130 episodes through `focus-text`, then all
three completed `copy-paste` seeds terminated at reward zero. The source text
ended in a significant space that DOM label normalization removed; after the
destination was verified, the source textarea also remained an eligible fill
target. Planner v44 preserves the bounded exact current value of non-sensitive
text controls and constrains an explicit one-source/one-destination copy/paste
instruction to fill only the destination with the exact source value. The
targeted matrix passes 10/10 in two actions per episode. A v44 PR diagnostic
then completed 17/18 because a slider direction error could appear only after
the bounded semantic repair budget had already been consumed. Planner v45
constrains the one direction that reduces distance before candidate decoding
and removes the slider action once satisfied. Targeted `form-sequence` passes
10/10 with 108 calls; fresh v45 smoke and PR pass 6/6 and 18/18. The interrupted
v43 run and v44 PR are diagnostic evidence, not scores promoted as the current
gate.

The v45 nightly passed the first 140 episodes, including copy/paste 10/10,
before four systematic `text-transform` failures. Its CAPTCHA-like value was
visible only in non-interactive spans, so the affordance-only planner context
could not observe it. BrowserSession now captures at most 2,000 characters of
real `body.innerText`; PlannerContext labels it as untrusted observation rather
than authority or an executable target. When a deictic text-entry objective,
one text target, and one non-label visible line agree, v47 constrains that exact
value before decoding. The targeted matrix passes 10/10 in two actions per
episode; fresh v47 smoke and PR pass 6/6 and 18/18. The interrupted v45 run is
diagnostic evidence, not a nightly score.
