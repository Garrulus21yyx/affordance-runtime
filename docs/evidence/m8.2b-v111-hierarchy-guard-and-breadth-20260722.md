# M8.2B v111 Hierarchy Guard and Breadth Gate

Date: 2026-07-22

## Breadth finding

The first post-v109 30-task × 2-seed breadth run completed 60/60 episodes with
no runtime, acceptance, provider, 429/retry, or unsupported-action errors, but
two `form-sequence-3` episodes received reward zero. Both traces showed the same
root cause: the newly added quoted hierarchical-target compiler treated the
terminal `Yes`/`No` button of an ordinary multi-step form as a tree target and
clicked it before the required dropdown selection.

## Generic repair

Hierarchical exact-target/ancestor compilation is now scoped to tasks whose
objective identifies a `tree`, `folder`, `file`, or `directory`. Ordinary
quoted buttons continue through the existing sequence constraints, which keep
terminal controls unavailable until the preceding scoped action is verified.
The launcher subprocess lock test also uses an isolated `XDG_RUNTIME_DIR`, so
a real benchmark holding the production user-global lock cannot make that unit
test nondeterministic. Production locking remains unchanged.
