# M8.6 G5 Generalization Proof Execution Plan

Date: 2026-07-24
Status: complete

## Goal and fixed boundaries

Close G5 with independently identified evidence for four profiles:

1. strict generalist;
2. strict generalist plus explicitly accepted skills;
3. historical compatibility;
4. declared ablations.

Generalization must be proved first on unseen local and synthetic conformance,
negative controls, provider/context fault injection, recovery injection, and
cross-surface routing. External evaluations may confirm the result only when
independently provisioned and must never be the sole evidence.

G5 does not authorize a task-family repair, hidden compatibility fallback,
automatic skill acceptance, external-suite provisioning, real credentials,
GitHub Actions, `.env` access, benchmark score promotion, or push. Missing
external assets remain an explicit unprovisioned evidence gap rather than a
fabricated pass.

- Legacy `generalization-v1` merges training, held-out, visual, and MiniWoB into
  one acceptance result and does not identify four isolated Runtime profiles.
- It has no accepted-artifact digest, compatibility identity, ablation
  declaration, negative-control metrics, or provider/recovery stress evidence.
- It can treat an external task result as a required acceptance input without
  proving independent local capability first.
- Existing governance, active-perception, recovery, local held-out, visual,
  WoT, and profile-loading tests are reusable evidence only after they are
  normalized into explicit source/profile/metric contracts.

## Implemented so far

- `m8.6-generalization-evidence-v1` requires exactly one digest-bound identity
  for each of the four profiles and rejects mixed revisions, hidden compatibility,
  undeclared ablations, or skill profiles without accepted artifact identity.
- Per-case evidence records expected success versus safe limitation, source and
  control coverage, effects, planner/model calls, and all hard safety counters.
- Aggregates and shared-case comparisons are recomputed from the ledger; a
  tampered aggregate, score-only claim, safety regression, invisible uplift, or
  missing strict control fails validation.
- The adaptive-routing conformance now passes its accepted skill profile digest
  and artifact ids into the real `RunCoordinator`; unskilled profiles carry no
  such identity.
- `generalization-v1` is retained only as an explicitly incomplete diagnostic
  and can no longer publish a G5 pass.
