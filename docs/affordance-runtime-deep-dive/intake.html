Conversion audit · 02 intake

自然语言如何编译成 TaskSpec

从原话到可执行语义要经过来源切分、模型解释、代码规范化和确定性准入。每一步都可能降维；关键是损失不能静默越过授权边界。

← 上一章：入口返回总览下一章：规划 →

本页结论：LLM 只产生不可执行草稿；Runtime 通过 source lineage、canonical IDs、coverage 与 validation 把“可能的理解”转换为“可被授权的任务”。不能证明的语义要进入澄清或拒绝，而不是被默认补全。

UserRequest→SourceLedger→LLMIntentDraft→IntentDraft→Canonical Obligation Graph→TaskSpec
02-A

UserRequest → SourceLedger

输入 INPUT

raw_text、conversation/attachment/target/profile refs、调用元数据。

→

输出 OUTPUT

whole-request 与 clause source units，包含 span、content hash、sensitivity 与引用标签。

转换者与规则：SourceLedgerBuilder 用代码规则切分整段和子句；model_context() 只向模型暴露允许的来源表示。
输入操作输出变化
raw_text切分 + 哈希source units保留 span，可重建原位置
附件/会话引用ref-onlylabel/hash正文不自动进入模型
敏感内容标记sensitivity约束后续暴露

保留语义

原文、字符位置、来源类别、完整内容哈希和引用身份。

可能的语义损失

按子句切分会弱化跨句指代、否定范围和语气；ref-only 会暂时隐藏引用内容。

风险与防护

整段 source unit 与 clause unit 同时存在，减少只看碎片的风险；后续 claim 必须回指 source ID。

失败出口

缺失必要来源时不产生 READY TaskSpec，转澄清。

02-B

SourceLedger → LLMIntentDraft / IntentDraft

输入 INPUT

预算化 source context、严格 system schema、目标/实体/效果等允许字段。

→

输出 OUTPUT

模型的 LLMIntentDraft，解码与归一化后成为 IntentDraft；仍不可执行。

转换者与规则：LLMIntentCompiler.compile 在模型调用预算内请求严格结构；解析失败可做有界 schema repair。
来源内容操作草稿字段表达变化
目标句语义抽取objective从开放文本压成单一目标
动作与结果分类requested_effects归入有限效果表示
修饰/偏好分槽preferences/constraints软偏好与硬约束可能误分
指代/缺口显式化ambiguities未识别歧义可能缺席

保留语义

模型识别出的 objective、entities、effects、preferences、outputs、criteria、constraints、claims、forbidden effects 与 provenance。

可能的语义损失

含蓄意图、语气强度、跨句关系、未进入 schema 的修辞与模型未识别歧义；结构化 schema 会把连续语义压成离散字段。

风险与防护

草稿标记为 non-executable；模型不能授予 capability/approval、不能产生 selector/coordinate，也不能声称已执行。

失败出口

schema 失败进入有界 repair；仍失败则 provider/validation failure，不继续。

02-C

Requested effects → Canonical claims / obligations

输入 INPUT

草稿 requested effects、source claims、value transfers、依赖和候选 evidence。

→

输出 OUTPUT

Runtime 编号的 claim/obligation DAG，含 predicate/effect、subject、relation、value source、depends_on、evidence requirements、blocking/terminal。

转换者与规则：CanonicalObligationCompiler 重建 ID 和 typed evidence；provider IDs 不继承权威，依赖只能指向已出现的效果。

保留语义

效果顺序、数据依赖、值来源、终端效果、来源 claim 与证据要求。

可能的语义损失

模型自由描述的步骤名称和非规范关系被重新编号/规范化；无法映射到 typed obligation 的修饰不会进入执行图。

风险与防护

规范化可能合并表面不同但语义相近的表达；唯一 ID、依赖校验、terminal/blocking/evidence 不变量阻止结构缺口。

失败出口

非法引用、循环、自依赖、缺证据的 blocking obligation 直接验证失败。

02-D

IntentDraft + obligation coverage → TaskSpec admission

输入 INPUT

规范草稿、义务图、source ledger、调用者 capabilities 与 policy。

→

输出 OUTPUT

不可变、revisioned、可哈希 TaskSpec，或 clarification/policy conflict/unsupported 结果。

转换者与规则：IntentDraftValidator.compile 与 deterministic coverage validator 决定准入；可选模型 reviewer 只有负向 veto 权。

保留语义

通过来源授权和覆盖证明的目标、效果、义务、约束、证据、禁止项和能力上限。

可能的语义损失

未被来源支持、与策略冲突、能力不支持或仍有重大歧义的内容不会进入 TaskSpec。这是显式拒绝，不是静默遗忘。

风险与防护

过严准入可能牺牲召回率；状态结果、provenance、source coverage 和 revision 让调用者可澄清后重编译。

失败出口

NEEDS_CLARIFICATION、POLICY_CONFLICT、UNSUPPORTED；只有 READY 进入 planning。

本页语义损失账本

转换边类型损失/弱化检测与恢复
UserRequest → Ledger表达降维跨句语用关系可能被 clause 切分弱化保留 whole-request 与 span
Ledger → Draft不确定性模型可能漏掉隐含约束或歧义schema、provenance、repair、coverage
Draft → Obligations规范化自由关系被收敛为 typed relationcanonical compiler validation
Draft → TaskSpec安全拒绝未授权/冲突语义不传播显式状态 + clarification revision
