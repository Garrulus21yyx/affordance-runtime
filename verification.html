Conversion audit · 06 verification

执行回执如何变成可证明终态

Runtime 不从 receipt 推断成功，而是重新观察环境，将证据分别归因到动作效果、当前步骤和整个任务。无法证明时必须保留 UNKNOWN 或 failure。

← 上一章：感知与执行返回总览下一章：恢复 →

本页结论：验证是一条独立信息链。它会丢弃执行器的“自我评价”，只接受当前环境证据；但观测盲区和证据归因仍可能造成假阴性或 UNKNOWN，所以 effect、step、task 三层不能合并。

ExecutionReceipt+Post Observation→VerificationEvidence→VerificationReport→Effect Decision→Step Progress→Terminal Readiness→TaskCompleted
06-A

Receipt + 新观测 → VerificationEvidence / Report

输入 INPUT

ActionContract.expected effect、criterion IDs、ExecutionReceipt，以及动作后重新捕获的当前 observation。

→

输出 OUTPUT

VerificationReport(status, evidence, reason)；evidence 含 verifier kind、target、observed/expected、criterion/requirement IDs、snapshot、strength。

转换者与规则：ProgressStage 捕获独立 post state，verifier ladder 按 typed criterion 比较 observed/expected；inconclusive 可触发 repair/active perception。
输入操作证据输出不采用内容
receipt.success不作完成证明执行背景执行器自报成功
post observation状态提取observed value未观测属性
criterion绑定比较expected + refs无来源自由判断
环境身份谱系绑定environment/snapshot旧 epoch 证据

保留语义

预期状态、实际观测、验证方式、强度、准则与需求谱系、当前环境身份。

可能的语义损失

未被 verifier 覆盖的页面变化、不可观察后端效果、短暂中间状态；receipt 的低层细节可能不进入语义证据。

风险与防护

可能出现“效果发生但看不见”的假阴性；verifier ladder、active perception 和 artifact refs 提供补证路径。

失败出口

passed/failed/inconclusive 分开；inconclusive 不降级成 success，failed 进入 progress/recovery。

06-B

VerificationReport → Action effect decision

输入 INPUT

report、contract expected effect、post state 与 recent outcome index。

→

输出 OUTPUT

本次动作效果 passed/failed/unknown，action outcome 记录与 progress signature。

转换者与规则：ActionOutcomeFlow/ProgressStage 把证据归因给具体 action key（kind、target、参数摘要等）。

保留语义

动作身份、目标、参数摘要、effect status、evidence refs 和 revision。

可能的语义损失

参数进入 digest 后原值不在索引 key 中；同义动作可能分成不同 key，或不同上下文动作被归到同一语义族。

风险与防护

错误归并影响重复检测；destination/subgoal 纳入摘要，revision 与 evidence refs 限制跨状态误用。

失败出口

同 revision 重复失败触发 no_progress_repeat；may_have_occurred 转 inspect post-state。

06-C

Effect evidence → Step completion / plan progress

输入 INPUT

active StepSpec completion criteria、VerificationReport、已有 completed steps/evidence。

→

输出 OUTPUT

criterion credit、completed_subgoal_ids、evidence_by_subgoal、下一 active step 或 reconciliation/replan。

转换者与规则：ProgressStage 区分“effect passed”与“criterion 可归因”；动作前也会对账已经满足的 current state。

保留语义

哪条 criterion 被哪份 verification evidence 满足、步骤依赖和已完成进度。

可能的语义损失

页面状态可能已满足但无法证明由当前步骤/来源导致；证据无法归因时不会给 credit，这不是把 effect 当失败，而是保持归因不确定。

风险与防护

过严归因可能空转；progress-credit invariant 显式识别“效果满足但无法给当前步骤记分”。

失败出口

reconcile、inspect、replan 或 progress failure；不会仅因 receipt success 推进步骤。

06-D

Plan progress + obligation evidence → Terminal readiness / TaskCompleted

输入 INPUT

terminal candidate、TaskPlan dependencies、completed evidence、task revision、observation epoch、target fingerprints。

→

输出 OUTPUT

READY/BLOCKED/UNKNOWN terminal decision；READY 且 task verification passed 后提交 final result 和唯一 TaskCompleted event。

当前转换者：TaskObligationViewCompiler/TerminalReadinessEvaluator 处理 legacy TaskPlan/PlanProgress 的窄 terminal readiness；runtime_terminal.TaskCompletionVerifier 主要检查最新独立 passed VerificationReport；commit_task_terminal_success 负责提交。
输入证据操作终态字段拒绝条件
completed subgoals依赖闭包prerequisites_complete缺节点/未完成
verification refs证据绑定SATISFIED完成但无 evidence
task/epoch/fingerprint当前性校验current binding旧 revision/epoch/target
final result冻结提交state.done + eventtask verification 未 passed

保留语义

窄 terminal candidate 对应的先决状态、证据引用、当前 task/observation identity 和最终结果。

可能的语义损失

最终 result 是面向调用者的摘要，不包含全部观察/动作历史；完整历史外置到 Trace/ArtifactStore。

风险与防护

摘要结果可能隐藏中间失败；TaskCompleted 事件与 evidence/trace API 保留可审计路径。

失败出口

BLOCKED/UNKNOWN 留在循环或恢复；缺独立 passed verification 时 TaskSpec-backed 任务不得成功终止。

当前实现：两条窄机制

一条是 legacy TaskPlan/PlanProgress 的 TerminalReadinessEvaluator；另一条是主要依赖最新独立 passed VerificationReport 的 TaskCompletionVerifier。二者都不能等同于完整 TaskSpec completion expression closure。

建议目标（尚未实现）

TaskSpec completion expression + TaskProgress evidence index + current observation + Evidence Validity Policy → TaskCompletionVerifier；全部 required criteria 满足后才由 RuntimeCommitter 提交 TaskCompleted。
